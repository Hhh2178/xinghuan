# 无限画布 2.0 开发计划

## 状态

本文件保留 v0.1.0 早期阶段计划和历史验收结构，不再单独承担当前项目状态入口。当前 gray 与 production 都已运行在 `v0.5.22`，早期 `Phase 3` 任务与素材闭环已完成；当前重点是 ComfyUI 机器池与工作流治理、项目级 harness、后台体验重设计和发布链路一致性。当前真实运行态以 `../README.md`、`progress.md`、`../../logbooks/releases/current-release-index.md`、`../../../ops/README.md` 和线上 `/api/status` 为准。

## Phase 0 - 选型与 POC

目标：确定可作为 2.0 主干的技术基底，或确认需要自研核心画布和节点系统。

任务：

- 建立候选项目评估表。
- 评估 Jaaz、T8、ComfyUI Web 类项目、React Flow 类项目、LiteGraph 类项目和其他候选。
- 检查许可证、维护状态、前后端结构、节点系统、执行引擎和部署成本。
- 选择 1-2 个候选做最小 POC。

验收：

- 至少产出一份候选基底评估报告。
- 至少完成一个能添加节点、连接、保存、执行 mock 任务的 POC。

## Phase 1 - 基础平台

目标：完成企业 Web 平台基础能力。

任务：

- 登录、账号、RBAC。
- 项目、画布、工作流、素材数据模型。
- 云端保存和打开。
- 独立后台框架。
- 科技黑工作台和后台基础 UI。

验收：

- 普通成员可以创建项目并保存云端画布。
- 管理员可以进入后台。
- 用户项目隔离生效。
- 未登录访问画布 API 会被拒绝。
- 登录页、后台和新增管理页面统一采用星幻科技风。

任务级拆分：

1. 认证门禁
   - 登录、退出、当前用户接口。
   - Web 登录守卫。
   - session cookie。
   - 灰度/生产必须通过服务器环境变量提供管理员初始密码，不使用本地默认密码。
2. 用户隔离
   - 画布列表按用户隔离。
   - 画布详情按用户隔离。
   - 输入素材、输出素材和资源库按用户隔离。
   - 自动验收覆盖管理员和普通成员互相不可见。
3. 统一后台骨架
   - 独立 `/admin` 页面。
   - 左侧导航、顶部状态、主内容表格、抽屉编辑器。
   - 管理员可访问，普通成员不可访问。
   - 后台视觉采用与登录页一致的星幻科技风。
4. 项目与数据模型
   - PostgreSQL 用户、项目、画布、素材、任务基础表。
   - 文件存储仍可先保留本地目录，路径通过配置注入。
   - 后续迁移对象存储时保持 API 不变。
5. 服务器灰度
   - 灰度域名继续使用 `canvas-next.hhh2121.xyz`。
   - 灰度端口继续使用 `127.0.0.1:18200`。
   - 部署前必须设置真实 bootstrap 管理员密码。
   - 验收必须包含 HTTPS 登录、画布保存、素材上传和用户隔离。

视觉验收：

- 登录页首屏必须是科技风，不出现 T8 原主题的浅色大面积背景。
- 后台首屏必须和登录页视觉一致，使用深色底、青绿/蓝色状态、高对比文字和 8px 内卡片圆角。
- 画板主体暂时保持 T8 成熟 UI，不重做节点和画布交互。
- 浏览器截图需覆盖未登录、登录后画板、后台首页三个状态。

## Phase 2 - 节点与模型治理

目标：完成通用生成节点和模型后台闭环。

状态：已完成灰度验收。当前验收 release 为 `20260606-0945-phase2-complete-gray`，三类通用节点、后台模型高级设置、动态 schema 参数、真实代理调用和 Worker 图像 Adapter 均已通过服务器与公网画布验证。

任务：

- 节点注册表和类型系统。
- Provider 管理。
- 模型目录。
- 参数 schema 编辑器。
- input profile 编辑器。
- 通用图像生成节点。
- 通用视频生成节点。

验收：

- 画布前端不再出现 API/服务商设置入口。
- 管理员能在统一后台新增、编辑、停用 Provider。
- 管理员能填写 Key 和 Base URL，并验证地址。
- 管理员能从上游拉取模型列表，拉取结果按语言、图像、视频三类给出建议。
- 拉取结果不会自动全量导入，必须由管理员选择性导入。
- 管理员能手动新增、编辑、停用和删除模型，并调整模型能力分类。
- 成员能通过通用图像节点生成图片。
- 多参考图端口能按后台配置动态出现。

任务级拆分：

1. 画布前端入口收口
   - 从 T8 画布顶部移除 API 设置按钮和弹窗。
   - 保留迁移期兼容加载，不破坏现有画布节点。
   - 验收：登录后画布顶部不再可见 `API 设置` 入口，画布仍可打开、创建、保存。
2. Provider schema 升级
   - 在 Provider 增加 `protocol`、`lastProbeStatus`、`lastProbeMessage`、`lastFetchedAt`。
   - Key 继续只保存加密字段和脱敏预览。
   - 验收：后台 Provider 列表不返回 Key 明文，数据库不包含测试 Key 明文。
   - 状态：第一版已完成，PostgreSQL 迁移为 `002_provider_model_framework.sql`。
3. Provider 验证和拉取 API
   - 新增草稿验证：`POST /api/admin/providers/probe`。
   - 新增已保存 Provider 验证：`POST /api/admin/providers/:id/probe`。
   - 新增草稿拉取模型：`POST /api/admin/providers/fetch-models`。
   - 新增已保存 Provider 拉取模型：`POST /api/admin/providers/:id/fetch-models`。
   - 支持 OpenAI 兼容、Gemini、RunningHub、Volcengine 的模型列表地址规则。
   - 验收：无 Key、错误 URL、HTML 登录页、401/403、正常模型列表都有明确错误或成功提示。
   - 状态：第一版已完成，RunningHub/Volcengine 高级探测后续继续细化。
4. 模型候选选择器
   - 拉取结果暂存为候选，不自动导入。
   - 支持搜索、全选/反选、分类筛选、分类覆盖。
   - 支持语言、图像、视频三类计数。
   - 验收：选择部分模型导入后，未选模型不会出现在模型目录。
   - 状态：后台第一版已完成。
5. 模型目录三分类管理
   - 模型目录按 `chat`、`image`、`video` 分区。
   - 支持手动新增、编辑、停用、删除、修改 Provider、修改能力分类。
   - 支持单模型 `protocolOverride` 和 `parameterSchema`。
   - 验收：后台可以把同一上游 Provider 的不同模型分配到不同能力区。
   - 状态：后台第一版已完成。
6. 画布模型消费 API
   - 新增或收敛 `GET /api/models`，只返回已启用模型。
   - 通用节点从后台模型目录读取选项。
   - 验收：禁用模型后，刷新画布节点下拉不再出现该模型。
   - 状态：已完成，图像/视频/LLM 节点均消费后台目录。
7. Provider Adapter
   - Worker 根据模型能力和 Provider 协议分派 Adapter。
   - Adapter 只在服务端解密 Key。
   - 验收：通用图像节点使用后台配置的真实图像模型生成成功，并写入任务日志。
   - 状态：已完成第一版，图像 Worker Adapter 与图像/语言/视频同步代理已通过灰度验收。
8. 视觉和操控验收
   - 后台 Provider 页面采用星幻科技风：左侧服务商列表，右侧编辑器，操作按钮固定清晰。
   - 模型选择器显示总数、当前显示数、已选数和三类分类数。
   - 桌面和窄屏截图均不得出现文字溢出、按钮错位或信息层级混乱。
   - 验收截图覆盖 Provider 列表、Provider 编辑器、模型拉取结果、选择导入弹窗、模型目录三分类。
   - 状态：已完成公网桌面、窄屏和真实画布联通截图验收。

## Phase 3 - 任务与素材闭环

目标：完成异步任务、worker、日志和输出素材落库。

状态：🔄 进行中。Phase 2 前置条件已经具备：PostgreSQL auth/admin repository、Redis/worker 队列、三类通用节点、`/api/models`、外部代理和 `grsai_draw` Worker Adapter 已通过灰度验收。Phase 3 不再重复建设基础队列，而是补齐“任务结果如何沉淀为可管理素材”的闭环。

任务：

- 任务状态机。
- 队列和 worker。
- Provider Adapter。
- 任务日志。
- 取消和重试。
- 输出素材落库。

验收：

- 任务成功、失败、取消、重试都可追踪。
- 输出素材能在项目素材空间查看。

任务级拆分：

1. 任务状态机收口
   - 明确任务状态集合：`queued`、`running`、`succeeded`、`failed`、`cancelled`，并约束状态迁移。
   - 区分“用户取消”“执行失败”“上游失败”“结果入库失败”等日志语义。
   - 后台任务列表展示最终状态、更新时间、核心结果摘要。
   - 验收：同一任务在 API、Worker、后台 UI 和持久层中的状态一致，不再出现 API 回写覆盖 Worker 终态。
2. 输出素材落库
   - Worker 在任务成功后，将 `imageUrls`、`videoUrls`、`audioUrls` 对应结果写入输出素材记录，而不只是写回任务 `result`。
   - 输出素材记录至少包含：用户、项目/画布归属、任务 ID、素材类型、源 URL、本地文件 URL、文件名、生成时间、来源模型/Provider。
   - 保持文件仍可先存本地目录，但素材索引进入统一 repository。
   - 验收：任务成功后，输出素材不仅能在 OutputNode 下载，也能在素材空间查到。
3. 素材空间联动
   - 输出素材写入后，资源库/API 能按用户与项目维度读取。
   - 画布/项目侧能看到本次生成的新素材，而不是只依赖节点上的临时 URL。
   - 明确去重策略：同一任务结果重复回写时不生成脏重复记录。
   - 验收：成员刷新后仍可在素材空间看到刚生成的图像/视频/音频。
4. 取消与重试
   - 后台支持取消 `queued/running` 任务。
   - 对失败或已取消任务支持重试，重试时保留原 payload 并生成新的执行日志。
   - 第一版允许“取消排队任务 + 重试创建新任务”，运行中协作式中断可后续增强，但 UI 和状态机必须先统一。
   - 验收：后台可追踪一次取消和一次重试的完整链路。
5. 画布与素材 repository 推进
   - 在 auth/admin 已切 PostgreSQL 的前提下，推进画布内容和素材索引 repository 设计与实现。
   - 保持文件路径和现有 `/files` 访问路径兼容，避免一次性改动对象存储协议。
   - 验收：画布元数据、输出素材索引和任务关联关系可在 PostgreSQL 中查询，不再只依赖文件目录扫描。
6. Phase 3 灰度验收与生产预检
   - 灰度至少新增：任务成功落库、任务失败、取消、重试、素材空间可见、OutputNode 下载与素材空间一致性验证。
   - 生产切换预检文档必须在 Phase 3 灰度验收后更新，而不是提前假定可切生产。
   - 验收：`canvas-next.hhh2121.xyz` 上完成 Phase 3 smoke 后，才进入 `canvas.hhh2121.xyz` 切换准备。

当前执行顺序：

1. Worker 输出写入输出素材与资源库。
2. 素材空间/API 读取闭环。
3. 取消/重试与后台任务交互收口。
4. 画布/素材 PostgreSQL repository 推进。
5. 更新生产预检并准备正式切换。

## Phase 4 - 创作增强

目标：补齐视频创作、批量、运镜和 Agent 能力。

任务：

- 首帧/尾帧视频节点。
- 多参考素材节点。
- 批量执行和拓扑执行。
- 运镜组合节点。
- Agent 辅助搭建工作流和 prompt。

验收：

- 用户能从素材到视频生成完成一个可复用工作流。
- Agent 能辅助创建或解释工作流，但不绕过权限。

## 开发原则

- 每个 Phase 必须可验收，不做“看起来做了但入口找不到”的功能。
- 代码提交和文档更新同步进行。
- 先打通一个真实 Provider，再扩展多个 Provider。
- 先保证节点体系正确，再堆节点数量。
