# 媒体节点比例、画布持久化与运行任务续接计划

## 目标

修复媒体节点初始比例和拉伸行为、文本节点缩放卡顿、输出视频刷新后丢失，以及生成任务在页面刷新或版本发布后不能自动续接的问题；先发布 Gray 验证，再以同一版本晋级 Production。

## 不变量

1. 普通画布保存、自动保存、刷新恢复和版本发布不得清理节点媒体或运行任务字段。
2. 只有“保存为工作流”可以清理媒体和运行时字段，而且必须只操作深拷贝。
3. 已完成的输出素材是画布状态；Output 节点挂载时不得用暂时为空的派生结果覆盖已保存素材。
4. 运行中的任务必须持久化远端任务标识。刷新或前端版本更新后只能继续查询原任务，不得重复提交。
5. 单个图片或视频的自动尺寸和手动拉伸都锁定素材固有比例；节点标题、文件信息等固定区域不参与媒体比例。
6. 多素材完整展示，使用响应式网格和 `object-fit: contain`，不以裁切代替布局。

## 已确认根因

- Upload 节点把 React Flow 测量高度当作显式用户高度，导致空节点高度在上传后继续锁定。
- Upload 多素材使用固定两列和固定最大高度，没有读取图片或视频固有尺寸。
- Output 节点只把 `direct*` 字段当作自身持久化素材来源；普通 `videoUrl/videoUrls` 在没有可收集上游时会被挂载 effect 回写为空。
- 工作流清理函数目前只由工作流 manifest 构建调用；普通画布 persistence 直接保存节点。刷新丢失的直接触发点优先按 Output 派生回写处理，同时增加边界测试防止清理函数外溢。
- Text 节点 resize 同时触发组件 state、双 RAF、ResizeObserver、layout effect 和 `transition-all`，形成重复布局与视觉拖尾。
- 当前生成节点的轮询主要由“提交成功”路径启动；需要核对并补齐从已持久化 `taskId/taskIds/taskRuns` 恢复轮询的挂载路径。

## 设计

### 单素材尺寸

设媒体比例为 `r = mediaWidth / mediaHeight`，节点横向固定区域为 `cx`，纵向固定区域为 `cy`：

```text
mediaWidth = nodeWidth - cx
mediaHeight = mediaWidth / r
nodeHeight = mediaHeight + cy
```

四角拖动时将指针产生的原始宽高投影到该约束线上，使横向或纵向拖动都能驱动同一比例。尺寸写入：

```ts
size: {
  w: number;
  h: number;
  mode: 'auto' | 'manual';
  mediaAspectRatio?: number;
}
```

旧 `data.size` 按手动尺寸兼容；普通 React Flow 测量高度不再自动升级为手动高度。

### 多素材布局

- 复用 Output 的媒体元数据和响应式列数算法。
- 单项完整 `contain`；混合横竖素材允许留边，不裁掉主体。
- 节点宽度、数量和素材比例共同决定列数与行高。

### 输出恢复

- 区分 Output 的“派生上游结果”和“已保存快照”。
- 初次恢复时，如果派生来源暂不可用，保留已保存的 `imageUrls/videoUrls/audioUrls`。
- 只有明确的上游结果变更或用户清空动作可以清空快照，不能由挂载空态触发。
- 增加普通画布 round-trip 测试，验证视频数组和 direct 字段不被工作流清理影响。

### 运行任务续接

- 任务提交后立即持久化 `taskId/taskIds/taskRuns` 和开始时间。
- 节点挂载时识别 `queued/submitting/polling/running` 状态及未完成任务标识。
- 通过幂等 resume guard 启动查询，成功后走与原轮询相同的结果归一化和物料化路径。
- 查询到失败、取消或不存在时展示真实终态；网络暂时失败保留任务标识并退避重试。
- 页面刷新和静态前端版本切换不取消服务器任务。Worker 重启后的任务行为继续由现有队列与任务仓储负责。

## 回归场景

- 单张竖图、横图、方图上传后的初始节点高度。
- 单视频读取 metadata 后的初始比例。
- 单素材从四个角横向、纵向和斜向拖动，媒体比例保持。
- 两个到十个混合比例素材在窄、中、宽节点中的完整展示。
- 文本节点连续拖动，尺寸跟手且结束后刷新保持。
- Output 含单视频和多视频时保存、刷新、再次自动保存，URL 不丢失。
- 保存为工作流后 manifest 不含媒体，但原画布节点仍保留媒体。
- 图像/视频任务处于 polling 时刷新页面，继续原 task ID 并回填结果。
- Gray 发布重启 API/Worker 后，已提交任务不由前端重复提交。
- 输出节点同时存在上游图片和已保存视频时刷新，按媒体类型独立恢复，不得写空视频数组。
- 视频节点再次生成时保留既有 `videoUrls`，新批次按 URL 去重追加到同一输出节点。
- 图像/视频节点新增“输出累积”开关，默认关闭；开启后才跨次生成追加，单次批次内始终逐项追加显示。

## 发布约束

- Gray 验证通过前不部署 Production。
- Production 复用 Gray 已验证版本，不额外递增版本。
- 本轮不执行 retention/prune。
- 不修改其他项目、代理服务、数据库内容或密钥。
