# Admin 后台信息架构与前端设计体系重构总计划

> **状态：** 已实施并以 v0.7.3 部署 Gray 与 Production；严格运行态验证通过
> **创建日期：** 2026-07-17
> **适用项目：** 星幻无限画布 Admin
> **替代范围：** 本计划在信息架构层面替代“固定五大工作域”的旧方案；既有业务协议、安全约束和已验证组件继续有效。
> **实施要求：** 每个阶段均须单独评审、实现、验证和同步文档，不允许一次性大爆炸切换。

## 1. 计划目标

将当前“5 个宽泛工作域 + 多层页面内页签 + 集中数据加载”的后台，重构为职责清晰、可深链、可独立授权、可渐进加载的 10 个一级业务域，并建立统一的后台前端视觉与交互设计体系。

完成后应达到以下结果：

- 管理员能够从一级导航直接判断功能归属，不需要在多个页面中试探查找。
- 每个业务页面拥有稳定 URL，可刷新恢复、收藏、分享和精确鉴权。
- 目录管理、对象编辑、运行观测、统计分析和审计追踪不再混用同一页面层级。
- 页面按路由独立加载数据，单域失败不拖垮整个后台。
- 全后台共享统一的导航、标题区、筛选区、表格、表单、Inspector、反馈和动效规范。
- 后续新增能力必须先确定业务域、页面类型、对象归属和权限点，再进入实现。

## 2. 本次不做什么

- 不修改画布端的信息架构和视觉系统。
- 不在本计划阶段重写后端业务协议或数据库模型。
- 不把 RunningHub 与 ComfyUI 合并成同一个抽象工作台。
- 不为了视觉统一强行把所有业务页面做成卡片墙。
- 不在一个版本中同时迁移全部页面。
- 不移除旧路由，直到新路由、权限、审计和回归验证全部完成。
- 不用装饰性动画掩盖数据加载或操作延迟。

## 3. 当前问题诊断

### 3.1 信息架构问题

当前后台通过 5 个工作域承载 12 个主标签，但用户治理、RunningHub 和 ComfyUI 页面内部仍继续嵌套本地页签，形成隐性的三级或四级导航。

典型混合包括：

- “组织与治理”同时容纳账号、用户组、权限、会话、用量和审计。
- “能力配置”同时容纳 Provider、模型、RunningHub、ComfyUI 和后台 AI 助手。
- “系统与发布”同时容纳任务运行、系统健康、运行参数和环境同步。
- RunningHub 页面内部同时处理工作流、AI 应用、Key 池和分析编辑。
- ComfyUI 详情内部同时处理实例配置、工作流和日志。

### 3.2 导航与路由问题

- 页面主要由 `activeTab` 和组件内部状态切换，缺少稳定层级路由。
- 页面内页签无法独立收藏、刷新恢复和分享。
- 浏览器前进后退无法完整表达管理路径。
- 权限控制只能围绕大页面处理，难以做到页面级和操作级授权。

### 3.3 前端架构问题

- `AdminApp` 同时承担认证、导航、全局数据获取、轮询和全部页面渲染分发。
- `loadAdminData()` 会集中请求多个业务域的数据。
- 页面状态、筛选条件和选中对象缺少统一的 URL/查询参数模型。
- 部分页面已经局部懒加载，但路由级边界和错误边界仍不完整。

### 3.4 设计体系问题

- 已有 Starlight 深色控制台基线，但规则分散在多个文件中。
- 字号、密度、焦点态、加载态、空状态和错误态缺少统一矩阵。
- 页面切换、抽屉、保存、刷新、列表更新和危险操作缺少统一动效标准。
- 当前部分辅助文字过小，不利于长时间管理操作和可访问性。
- 页面不断新增局部类名和定制布局，复用边界不够明确。

## 4. 目标信息架构

### 4.1 十个一级业务域

| 序号 | 一级业务域 | 核心职责 | 不负责 |
| --- | --- | --- | --- |
| 1 | 运营总览 | 全局状态、关键指标、告警、待办和快捷入口 | 具体对象编辑 |
| 2 | 账号与组织 | 账号、用户组、成员关系、会话治理 | 权限策略编辑、业务审计 |
| 3 | 权限与安全 | 权限策略、访问边界、安全事件、敏感操作 | 普通账号资料维护 |
| 4 | Provider 与模型 | Provider、模型目录、能力标签、路由与健康测试 | RH/ComfyUI 工作流内容 |
| 5 | RH 管理 | RH 工作流、RH AI 应用、RH Key 池、测试和运行记录 | ComfyUI 实例与工作流 |
| 6 | ComfyUI 管理 | 实例、连接器、实例工作流、共享发布、日志和健康 | RH Key 与 RH 应用 |
| 7 | 内容与资源 | 公共资源、生成库、分类标签、公告与内容治理 | 任务调度和运行监控 |
| 8 | 任务与运行 | 任务列表、队列、失败重试、运行详情和实时日志 | 用量排行与审计调查 |
| 9 | 数据分析与审计 | 用量、成本、排行、审计日志和事件调查 | 运行参数编辑 |
| 10 | 系统与发布 | 系统健康、运行参数、环境同步、版本和发布状态 | 业务目录编辑 |

### 4.2 一级导航规则

- 左侧一级导航固定展示十个业务域，允许折叠为仅图标模式。
- 一级导航不直接承载危险操作。
- 每个业务域展开后显示稳定的二级页面树，不使用横向页签替代主导航。
- 当前域、当前页面和当前对象必须同时可识别。
- 导航顺序按“看全局 → 管主体 → 配能力 → 管平台 → 管内容 → 管运行 → 做分析 → 管系统”排列。
- 一级导航支持关键字搜索，但搜索不改变业务归属。
- 无权限的业务域默认隐藏；可申请权限的业务域可显示锁定态和申请入口。

### 4.3 页面层级模型

统一采用四层模型：

1. 业务域：一级导航。
2. 页面：列表、总览或配置工作台。
3. 对象：账号、Provider、工作流、实例、任务等详情。
4. 子视图：对象内部的概览、配置、版本、日志等标签。

子视图可以使用页签，但必须满足：

- 页签属于同一个对象，而不是不同业务页面。
- 页签状态写入 URL。
- 页签之间共享同一对象身份和权限边界。
- 不允许在子视图中再次嵌套同级页签。

## 5. 十大业务域页面树与职责

### 5.1 运营总览 `/admin/overview`

二级页面：

- 运营驾驶舱 `/admin/overview`
- 告警中心 `/admin/overview/alerts`
- 管理待办 `/admin/overview/actions`

驾驶舱模块：

- API、Worker、RH、ComfyUI 总体健康。
- 今日任务量、成功率、平均耗时、失败趋势。
- 活跃账号、资源增长、用量异常。
- 待发布配置、待处理冲突和高风险告警。
- 可下钻的 KPI，不展示无法继续操作的装饰数字。

### 5.2 账号与组织 `/admin/organization`

二级页面：

- 组织总览 `/admin/organization`
- 账号管理 `/admin/organization/accounts`
- 用户组 `/admin/organization/groups`
- 成员关系 `/admin/organization/memberships`
- 会话管理 `/admin/organization/sessions`

对象路由示例：

- `/admin/organization/accounts/:accountId`
- `/admin/organization/groups/:groupId`
- `/admin/organization/sessions/:sessionId`

职责边界：

- 本域管理“谁存在、属于哪个组、当前是否在线”。
- 权限策略只展示摘要和跳转，不在本域直接编辑。
- 账号详情允许查看基本信息、所属组、会话和近期活动摘要。

### 5.3 权限与安全 `/admin/security`

二级页面：

- 权限总览 `/admin/security`
- 角色与策略 `/admin/security/policies`
- 对象授权 `/admin/security/grants`
- 安全事件 `/admin/security/events`
- 敏感操作记录 `/admin/security/sensitive-actions`

核心规则：

- 保留 revision 并发保护和冲突恢复机制。
- 策略编辑必须先显示影响范围，再允许发布。
- 发布、撤销、批量授权必须进入审计链路。
- 权限矩阵负责编辑，账号页面只消费权限摘要。

### 5.4 Provider 与模型 `/admin/capabilities`

二级页面：

- 能力总览 `/admin/capabilities`
- Provider `/admin/capabilities/providers`
- 模型目录 `/admin/capabilities/models`
- 能力标签 `/admin/capabilities/tags`
- 路由与优先级 `/admin/capabilities/routing`
- 连通性测试 `/admin/capabilities/health`
- 后台 AI 助手配置 `/admin/capabilities/admin-assistant`

对象路由示例：

- `/admin/capabilities/providers/:providerId`
- `/admin/capabilities/models/:modelId`

职责边界：

- Provider 表达外部或内部能力提供方。
- 模型表达可被任务和应用消费的能力实体。
- RH 和 ComfyUI 只引用 Provider/模型，不在本域编辑其工作流内容。

### 5.5 RH 管理 `/admin/rh`

二级页面：

- RH 总览 `/admin/rh`
- 工作流 `/admin/rh/workflows`
- AI 应用 `/admin/rh/apps`
- Key 池 `/admin/rh/keys`
- 调用测试 `/admin/rh/tests`
- 运行记录 `/admin/rh/runs`

对象路由示例：

- `/admin/rh/workflows/:catalogId`
- `/admin/rh/apps/:catalogId`
- `/admin/rh/keys/:keyId`
- `/admin/rh/runs/:runId`

RH 对象编辑要求：

- 工作流与 AI 应用是两个独立目录，不再用组件本地页签切换。
- Key 池独立展示可用性、限额、最近错误、关联目录和轮换状态。
- AI 分析填充作为编辑器辅助能力，不与外部托管助手混淆。
- 测试结果必须保留请求摘要、输入映射、输出定义和失败原因。

### 5.6 ComfyUI 管理 `/admin/comfyui`

二级页面：

- ComfyUI 总览 `/admin/comfyui`
- 实例管理 `/admin/comfyui/instances`
- 工作流目录 `/admin/comfyui/workflows`
- 共享发布 `/admin/comfyui/publications`
- 连接器与版本 `/admin/comfyui/connectors`
- 健康与日志 `/admin/comfyui/observability`

对象路由示例：

- `/admin/comfyui/instances/:instanceId`
- `/admin/comfyui/workflows/:workflowId`
- `/admin/comfyui/publications/:publicationId`

职责边界：

- 实例配置、实例工作区和共享发布保持明确的源与目标关系。
- `baseUrl`、`reportedBaseUrl` 和地址来源必须分别展示。
- 实例详情的配置、工作流、日志可以作为对象子视图，但 URL 必须稳定。
- 推送共享区属于显式发布动作，必须确认、反馈和审计。

### 5.7 内容与资源 `/admin/content`

二级页面：

- 内容总览 `/admin/content`
- 公共资源 `/admin/content/public-resources`
- 生成库 `/admin/content/generation-library`
- 分类与标签 `/admin/content/taxonomy`
- 公告管理 `/admin/content/announcements`
- 回收与保留策略 `/admin/content/retention`

核心规则：

- 公共资源和生成库共享资源卡片与媒体预览语言。
- 图片、视频、音频预览优先完整展示主体，统一使用 `contain`。
- 资源转公开、删除、恢复和保留策略必须有明确状态反馈。
- 公告属于内容触达，不放入系统发布。

### 5.8 任务与运行 `/admin/runtime`

二级页面：

- 运行总览 `/admin/runtime`
- 任务列表 `/admin/runtime/tasks`
- 队列与槽位 `/admin/runtime/queues`
- 失败与重试 `/admin/runtime/failures`
- 实时运行日志 `/admin/runtime/logs`

对象路由示例：

- `/admin/runtime/tasks/:taskId`
- `/admin/runtime/queues/:queueId`

核心规则：

- 列表刷新不得打断筛选、滚动、选中对象和复制操作。
- 任务详情使用 Inspector 或独立详情路由，包含阶段、输入摘要、输出、错误和日志。
- 重试、取消和终止必须根据任务状态显示，不展示无效按钮。
- 队列与槽位负责实时运行状态，不承担历史统计排行。

### 5.9 数据分析与审计 `/admin/analytics`

二级页面：

- 分析总览 `/admin/analytics`
- 用量分析 `/admin/analytics/usage`
- 成本与配额 `/admin/analytics/costs`
- 账号排行 `/admin/analytics/accounts`
- 用户组排行 `/admin/analytics/groups`
- 审计日志 `/admin/analytics/audit`
- 事件调查 `/admin/analytics/investigations`

核心规则：

- 运行实时数据与历史分析分离。
- 排行、趋势和明细表共享同一筛选口径与时间范围。
- 审计日志不可在前端静默修改或删除。
- 从审计对象可跳转到账号、任务、资源、策略或系统配置详情。

### 5.10 系统与发布 `/admin/system`

二级页面：

- 系统总览 `/admin/system`
- 系统健康 `/admin/system/health`
- 运行参数 `/admin/system/settings`
- 环境同步 `/admin/system/environment-sync`
- 版本与发布 `/admin/system/releases`
- 变更与回滚 `/admin/system/changes`

核心规则：

- 健康观测和参数编辑分成不同页面。
- 环境同步使用源环境、目标环境、差异、选择、确认和结果六阶段流程。
- 发布状态只呈现经过后端确认的版本与环境信息。
- 参数保存必须显示当前值、目标值、生效范围、是否需要重启和审计原因。

## 6. 全局导航与页面框架

### 6.1 桌面端框架

页面从左到右分为：

- 一级导航：业务域。
- 二级导航：当前业务域页面树。
- 主工作区：列表、编辑器、仪表盘或详情。
- Inspector：当前对象的详情、关联、审计和快捷操作。

顶部栏固定承载：

- 当前环境和版本。
- 全局搜索。
- 告警入口。
- 后台 AI 助手入口。
- 当前管理员与退出入口。

### 6.2 页面标题区

统一包含：

- 面包屑。
- 页面标题和一句职责说明。
- 当前数据更新时间与刷新策略。
- 主操作按钮，最多一个。
- 次操作进入下拉菜单或工具栏。

### 6.3 窄屏策略

- 小于 1280px 时二级导航允许折叠。
- 小于 1024px 时 Inspector 改为覆盖抽屉。
- 小于 768px 时一级导航改为临时抽屉，表格优先保留关键列。
- 后台移动端只保证巡检、查看、确认和紧急操作；复杂矩阵和大型编辑器提示使用桌面端。

## 7. 统一视觉设计规范

### 7.1 视觉方向

延续 Starlight 深色专业控制台，但降低装饰性发光，强化信息层级和长时间可读性。

关键词：

- 冷静、精密、可信。
- 高信息密度但不拥挤。
- 结构优先于装饰。
- 状态颜色只表达语义。

### 7.2 色彩 Token

建议保留并语义化现有色板：

| Token | 建议值 | 用途 |
| --- | --- | --- |
| `color.bg.canvas` | `#0B0C10` | 页面背景 |
| `color.bg.surface` | `#171920` | 主面板 |
| `color.bg.elevated` | `#1F2128` | 抽屉、浮层、强调面板 |
| `color.border.default` | `#2D2F36` | 普通边框 |
| `color.border.strong` | `#414550` | 聚焦分隔 |
| `color.accent.primary` | `#66FCF1` | 当前选中、主操作、关键数据 |
| `color.text.primary` | `#F4F7FB` | 正文和标题 |
| `color.text.secondary` | `#B4BEC5` | 次级说明 |
| `color.text.muted` | `#8E999F` | 元信息，禁止承载关键状态 |
| `color.status.success` | `#2ECC71` | 成功、健康 |
| `color.status.warning` | `#F1C40F` | 风险、等待处理 |
| `color.status.danger` | `#E74C3C` | 失败、删除、断开 |
| `color.status.info` | `#4DA3FF` | 普通信息与处理中 |

要求：

- 选中、成功、允许不得共用同一种颜色语义。
- 正文对比度至少达到 WCAG AA。
- 禁止用低对比灰色表达错误、禁用原因或关键时间。
- 图表颜色必须配合标签、纹理或形状，不依赖颜色单独区分。

### 7.3 字体与字号

字体建议：

- 中文与 UI：`Inter`、`Noto Sans SC`、`PingFang SC`、`Microsoft YaHei` 依次回退。
- ID、请求号、日志与代码：`JetBrains Mono` 或等宽字体。

字号层级：

| 场景 | 字号/行高 | 字重 |
| --- | --- | --- |
| 页面标题 | 24/32 | 650 |
| 区块标题 | 18/26 | 600 |
| 面板标题 | 16/24 | 600 |
| 正文与表单 | 14/22 | 400 |
| 表格正文 | 13/20 | 400 |
| 标签与元信息 | 12/18 | 500 |
| KPI 数字 | 28/34 | 650 |

禁止把 10px 或 11px 作为承载业务信息的常规字号。

### 7.4 间距、尺寸与圆角

- 基础间距单位：4px。
- 页面主间距：24px。
- 区块间距：20px。
- 面板内边距：16px 或 20px。
- 紧凑表格行高：40px；标准表格行高：48px。
- 表单控件高度：36px；主按钮高度：38px。
- 小圆角：4px；面板圆角：6px；浮层圆角：8px。
- 不使用大面积 16px 以上圆角制造消费级卡片感。

### 7.5 层级和阴影

- 主要层级依赖背景明度和边框，不依赖厚重阴影。
- 抽屉、Popover 和 Modal 才使用明确投影。
- 发光只用于非常短暂的焦点或实时状态变化，不作为常驻装饰。

## 8. 统一组件规范

### 8.1 页面组件

- `AdminPageShell`：页面骨架、面包屑、标题、刷新状态。
- `AdminDomainNav`：一级业务域导航。
- `AdminSectionNav`：二级页面树。
- `AdminPageHeader`：标题、说明和页面操作。
- `AdminFilterBar`：搜索、筛选、时间范围和已选条件。
- `AdminInspector`：对象详情和关联信息。
- `AdminSaveBar`：脏状态、验证、保存和放弃。

### 8.2 数据展示组件

- `AdminDataTable`：排序、筛选、列设置、分页和行选择。
- `AdminMetric`：指标、趋势、状态和下钻入口。
- `AdminStatusPill`：统一状态映射。
- `AdminDescriptionList`：对象元信息。
- `AdminTimeline`：审计、发布和任务阶段。
- `AdminLogViewer`：虚拟滚动、搜索、复制和自动跟随。
- `AdminMediaPreview`：图片、视频和音频完整预览。

### 8.3 操作组件

- 主操作每个页面最多一个。
- 行操作默认最多两个直接按钮，其余进入菜单。
- 删除、发布、同步、终止、撤权等高风险操作必须二次确认。
- 确认内容必须说明对象、影响范围和是否可恢复。
- 批量操作必须显示已选数量、跨页规则和失败明细。

### 8.4 表单规范

- 标签置于控件上方，必填、帮助和错误信息位置固定。
- 保存前进行本地校验，后端错误映射到具体字段和页面级摘要。
- 离开脏表单前必须提醒。
- 异步验证显示进行中状态，禁止无反馈等待。
- JSON、Schema 和大段参数使用专门编辑器，不塞入普通多行输入框。

### 8.5 表格规范

- 默认使用服务端分页、筛选和排序。
- 长 ID 截断显示，支持一键复制和完整查看。
- 行点击进入 Inspector，行内交互不得意外触发行选择。
- 操作列固定在右侧，关键身份列固定在左侧。
- 空、加载、错误、无权限和筛选无结果必须有不同状态。

## 9. 页面状态矩阵

每个路由必须实现：

| 状态 | 必须表现 |
| --- | --- |
| 首次加载 | 页面级骨架，保留稳定布局 |
| 局部刷新 | 保留旧数据并显示轻量刷新指示 |
| 空数据 | 解释原因并给出符合权限的下一步 |
| 筛选无结果 | 保留筛选条件并提供清空入口 |
| 请求失败 | 展示失败范围、错误摘要和重试 |
| 部分失败 | 正常区域继续工作，失败模块独立恢复 |
| 无权限 | 说明缺失权限，不泄露敏感对象内容 |
| 连接中断 | 显示最后更新时间和恢复动作 |
| 保存中 | 锁定重复提交，保留可读内容 |
| 保存成功 | 就近反馈并更新脏状态 |
| 冲突 | 展示本地值、远端值和安全处理方式 |

## 10. 交互动效规范

### 10.1 动效原则

- 动效解释层级、状态变化和操作结果，不做纯装饰。
- 同一交互只使用一个主运动方向。
- 数据密集页面避免整页大幅位移。
- 支持 `prefers-reduced-motion`，关闭位移和循环动画。

### 10.2 时长与曲线

| 类型 | 时长 | 曲线 |
| --- | --- | --- |
| Hover、按压 | 80–100ms | `ease-out` |
| 状态切换、折叠 | 140–180ms | `cubic-bezier(0.2, 0, 0, 1)` |
| Popover、菜单 | 140ms | `cubic-bezier(0.2, 0, 0, 1)` |
| Inspector、抽屉 | 220–260ms | `cubic-bezier(0.2, 0, 0, 1)` |
| Modal | 180–220ms | `cubic-bezier(0.2, 0, 0, 1)` |
| 页面内容过渡 | 160–220ms | 淡入 + 最大 8px 位移 |
| 成功高亮 | 600–900ms | 渐隐，不循环 |

### 10.3 具体交互

- 一级导航展开：宽度与文字透明度同步，不推动主内容两次重排。
- 二级页面切换：旧内容快速淡出，新骨架或内容淡入。
- Inspector：从右侧进入，背景内容不缩放。
- 保存成功：保存栏状态切换并短暂高亮被更新字段。
- 表格实时更新：只高亮发生变化的行，不闪烁整个表格。
- 新任务进入：在排序规则允许的位置插入，并使用一次性强调。
- 危险确认：Modal 淡入；禁止抖动、红色脉冲等施压动效。
- 加载：优先骨架或静态进度，不使用高频闪烁 shimmer。
- Toast：右上角进入，自动消失前允许悬停暂停；严重错误不自动消失。

## 11. 可访问性与键盘交互

- 所有可操作元素均可通过键盘到达。
- 焦点环在深色背景上保持清晰，不能只靠背景色变化。
- 抽屉和 Modal 打开时正确管理焦点，关闭后返回触发点。
- 状态变化通过 `aria-live` 适度播报，实时日志不逐行打扰读屏。
- 图标按钮必须有可访问名称和 Tooltip。
- 表格排序、行选择和批量操作提供明确语义。
- 最小点击目标桌面端 32px，触屏端 44px。
- `prefers-reduced-motion` 下取消非必要位移、缩放和循环状态动画。

## 12. 前端技术架构

### 12.1 路由模型

建立声明式路由配置，至少包含：

- `domainId`
- `routeId`
- `path`
- `label`
- `icon`
- `permission`
- `loader`
- `refreshPolicy`
- `breadcrumb`
- `searchSchema`

旧的 `AdminTabId` 逐步迁移为 `AdminRouteId`，禁止继续向单层标签联合类型堆叠页面。

### 12.2 应用拆分

目标结构：

```text
apps/admin/src/
  app/
    admin-app.tsx
    admin-router.tsx
    route-registry.ts
    admin-shell.tsx
  domains/
    overview/
    organization/
    security/
    capabilities/
    rh/
    comfyui/
    content/
    runtime/
    analytics/
    system/
  components/
    navigation/
    data-display/
    feedback/
    forms/
    overlays/
  design-system/
    tokens.css
    motion.css
    typography.css
    primitives.css
```

### 12.3 数据加载

- 应用壳只加载身份、权限摘要、环境和版本。
- 每个路由独立声明首屏数据依赖。
- 对象详情在选中或进入详情路由后加载。
- 大目录和日志必须分页或虚拟化。
- 页面切换取消不再需要的请求。
- 同一对象的摘要和详情使用一致缓存键。
- 写操作完成后只失效相关域数据，禁止默认重新加载整个后台。

### 12.4 刷新策略

| 页面类型 | 默认策略 |
| --- | --- |
| 运营总览 | 30 秒增量刷新 |
| 系统健康 | 10–15 秒刷新 |
| 任务与队列 | 活跃任务期间 3–5 秒，空闲时降频 |
| 运行日志 | 流式或 2–3 秒增量 |
| 目录与配置 | 手动刷新，保存后精确失效 |
| 用量分析 | 手动或 60 秒以上刷新 |
| 审计日志 | 手动刷新，调查视图保持快照 |
| 编辑表单 | 编辑期间禁止外部刷新覆盖 |

### 12.5 错误边界

- 应用壳错误边界。
- 业务域错误边界。
- 页面模块错误边界。
- Inspector 独立错误边界。

局部错误不得自动清空用户当前筛选、草稿或选中对象。

## 13. 权限、审计和安全

- 一级域、二级页面、对象详情和操作按钮分别绑定权限点。
- 前端隐藏或禁用只用于体验，后端必须继续强制鉴权。
- 高风险写操作必须提交原因或确认上下文。
- 审计至少记录操作者、对象、前后值摘要、结果、时间和请求标识。
- 敏感 Key 默认遮罩，查看和复制均产生安全审计。
- URL 中不得写入 Token、Key、Cookie 或其他秘密。
- 无权限错误不得泄露对象是否存在及其敏感属性。

## 17. 风险与应对

| 风险 | 应对 |
| --- | --- |
| 新旧导航并存导致入口重复 | 维护唯一旧→新映射，迁移完成后按阶段关闭旧入口 |
| 路由拆分造成权限遗漏 | 路由注册强制声明权限，并用自动测试覆盖 |
| 页面拆分但 API 仍返回过大聚合 | 先在前端隔离 loader，再逐步补摘要与分页接口 |
| 全局样式调整引发大量视觉回归 | Token 与组件分层迁移，不直接全局覆盖所有旧类名 |
| 实时刷新影响编辑 | 路由刷新策略与表单脏状态联动，编辑期间禁止覆盖 |
| RH 与 ComfyUI 再次抽象合并 | 在路由、目录、类型和文档中保持独立命名空间 |
| 十个一级入口过长 | 支持折叠、分组标签和搜索，但不重新合并职责 |
