# 统一权限平台防回归实施计划

**日期：** 2026-07-15
**目标环境：** Gray
**生产环境：** 本阶段禁止修改

## 一、交付目标

本计划不是一次权限数据补丁，而是补齐权限平台的运行状态机、数据协调、统一后台、发布门禁和真实账号验收，使“新版过滤先上线、权限数据和后台仍未就绪”的发布顺序无法再次发生。

## 二、实施批次

### 批次 A：运行内核与门禁

新增：

- `permission-runtime.ts`
- `permission-readiness.ts`
- 对应单元测试

交付：

- `legacy / shadow / enforced` 三态运行模式。
- `shadow` 同时计算新旧结果，但旧结果实际生效。
- `enforced` 启动前执行就绪检查。
- 当前灰度的 `0 published / 0 rules` 状态必须被门禁拒绝。

### 批次 B：幂等协调迁移

新增：

- `permission-reconciliation.ts`
- `scripts/reconcile-permissions.ts`
- `scripts/verify-permission-readiness.ts`

交付：

- `dry-run / apply / verify`。
- 缺失旧策略不得静默解释为允许。
- 可通过显式参数处理历史缺失策略。
- 存量授权转换为精确 Subject/Action 规则。
- 新增 Subject 继续保持 `restricted`。
- 重复执行第二次无数据变化。

### 批次 C：统一运行链路

接入：

- Provider 模型目录与执行。
- RunningHub 目录与执行。
- 公共资源目录与使用。
- 节点能力目录与执行入口。

交付：

- 同一对象的目录可见性和直接执行使用同一权限决策。
- 调用方只使用稳定 Subject Key helper，不自行拼接权限语义。
- `shadow` 期间不改变普通成员原有可见结果。

### 批次 D：统一后台

新增统一权限 API client 与面板，替换固定 `deny` 数组编辑器。

交付：

- Subject 发布状态。
- 用户组规则。
- 单账号覆盖规则。
- 动作级授权。
- 直接、继承、覆盖和最终生效状态。
- 影响人数预览、revision 冲突和审计原因。
- 旧策略只进入迁移诊断，不再作为后台编辑权威。

### 批次 E：发布基础设施

交付：

- Gray prepare/verify 接入权限 readiness。
- `enforced` 且 readiness 失败时部署验证失败。
- Shadow 差异汇总和异常目录归零告警。
- 权限数据备份、回滚记录和验收模板。

### 批次 F：灰度验收

必须覆盖：

- 管理员。
- 未分组成员。
- 命名组成员。
- 单账号 allow 覆盖组 deny。
- 单账号 deny 覆盖组 allow。

逐项验证：

- 图像模型。
- 视频模型。
- LLM / 音频模型。
- RH AI 应用和工作流。
- 公共资源。
- 节点入口。
- 直接执行。

## 三、发布顺序

1. 先部署 `shadow`。
2. 执行 dry-run 并保存报告。
3. 明确处理所有缺失组策略。
4. 执行 apply。
5. 执行 readiness。
6. 用真实普通账号验证 shadow 结果。
7. 经确认后再切换 Gray 为 `enforced`。
8. 再次执行真实账号验证和观察。

任何失败都回到 `shadow`，不删除已经协调好的新权限数据。

## 四、完成定义

- 当前灰度错误形态被自动门禁识别。
- 新旧权限差异可观测。
- 数据协调幂等。
- 后台和运行时只有一个权威权限来源。
- Gray 真实普通账号验收通过。
- 代码审核、版本、发布日志、验证日志和当前状态索引全部更新。
