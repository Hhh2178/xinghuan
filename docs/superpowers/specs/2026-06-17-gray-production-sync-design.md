# 灰度正式同步设计

## 目标
为灰度与正式后端提供账号与服务商的双向同步能力，支持源/目标环境手动选择、差异预览、逐项勾选、全选与冲突裁决，避免两套环境数据长期分叉。

本次补充目标：

- 将“服务商同步”升级为“服务商 + 其关联模型配置”的整包同步。
- 将页面文案从工程术语改成后台运营人员能直接理解的表达。

## 范围
- 同步对象：用户、Provider、Provider 关联模型
- 同步方向：gray -> production、production -> gray
- 同步粒度：逐项选择，支持全选/全不选
- 同步策略：先预览，再执行
- 敏感字段：包含用户密码与 Provider API Key

## 非目标
- 不做自动定时同步
- 不做多环境广播同步
- 不做任意表结构级复制
- 不同步任务、日志、审计、素材等运行态数据
- 当前版本不做目标环境多余用户、服务商、模型的自动删除

## 界面
新增“环境同步”后台页，包含：
- 从哪里复制
- 同步到哪里
- 账号列表
- 服务商（含模型）列表
- 差异预览区
- 冲突处理区
- 执行结果区

列表支持：
- 勾选
- 全选

## 交互流程
1. 选择“从哪里复制”和“同步到哪里”。
2. 拉取两侧用户、服务商和模型数据。
3. 生成差异预览。
4. 勾选要同步的账号或服务商。
5. 对“两边内容不一致”的项逐项选择“以左侧环境为准”或“保留右侧当前数据”。
6. 提交同步。
7. 记录结果与审计日志。

## 冲突规则
- 同自然键对象内容不同视为冲突
- 冲突项默认不自动覆盖
- 必须人工选择以左侧环境为准或保留右侧环境
- 允许对每条记录单独决策

## 数据规则
- 用户同步包含：邮箱、昵称、角色、禁用状态、密码
- Provider 同步包含：名称、Base URL、协议、启用状态、API Key、备注
- 勾选服务商同步时，必须同时同步该服务商下的全部模型配置
- 模型同步包含：
  - `providerId`
  - `modelId`
  - `displayName`
  - `capability`
  - `enabled`
  - `executionMode`
  - `inputProfile`
  - `inputCapabilities`
  - `capabilityTags`
  - `testState`
  - `parameterSchema`
  - `advancedConfig`
  - `protocolOverride`
- 自然键规则：
  - 用户：`email`
  - 服务商：`name`
  - 模型：`provider.name + capability + modelId`
- 目标端若已存在同名服务商，复用目标端服务商 ID，并将同步过来的模型重新挂接到该目标端服务商 ID
- 当前版本只做新增和覆盖，不做删除

## 审计
每次同步必须写入：
- 执行人
- 源环境
- 目标环境
- 选择项列表
- 冲突裁决
- 成功/失败结果
- 服务商同步涉及的模型数量

## 安全
- 仅管理员可访问
- 同步前必须二次确认
- 不在页面中直接展示明文敏感字段
- 同步结果必须可追溯
- 预览中只展示模型数量和配置摘要，不直接展开长 JSON

## 验证
- 源/目标切换正确
- 用户与 Provider（含模型）的全选可用
- 冲突项可逐项裁决
- 密码与 API Key 可正确同步
- Provider 同步后模型配置也同步到目标环境
- 审计日志落库
- 失败项不影响其他已选项
