# RunningHub 分组筛选抽屉设计

## 背景

当前 RunningHub 管理工作台把分组管理器直接插入条目 rail 的文档流。分组按钮、分组操作和条目滚动区缺少清晰边界，导致分组内容视觉上覆盖条目卡片，并压缩可用于标题、备注和 Schema 摘要的空间。

## 目标

- 分组管理不再占用条目列表的常驻宽度或高度。
- 分组筛选仍可高频操作，且当前筛选状态始终可见。
- 抽屉打开时形成明确的模态层级，不允许背景条目被误操作。
- 保留现有分组 CRUD、启停、删除和条目计数行为。
- 桌面端 1920×1080 下，条目标题、备注和底部状态信息保持可读。

## 交互结构

1. 条目 rail 顶部保留目录标题、说明和新增条目操作。
2. 在标题区域增加“分组筛选”触发器，展示当前分组名称和当前范围条目数。
3. 点击触发器后，打开独立的分组抽屉：
   - 使用不透明背景和页面遮罩；
   - 通过 portal 或 workspace 根层渲染，不进入条目列表的 grid 流；
   - 固定宽度约 300px，内部列表独立滚动；
   - 支持 `Esc`、遮罩点击和关闭按钮关闭。
4. 抽屉内容按“全部条目、命名分组、未分组”组织；每行显示名称、数量和启停状态。
5. 新建、启用/停用、删除仍使用现有 handler；操作按钮使用图标并提供 title/aria-label。
6. 选择分组后更新现有 `selectedGroupId`，关闭抽屉，条目列表按现有过滤逻辑刷新。

## 视觉规则

- 抽屉与背景内容使用明显的层级差：遮罩、实色面板、明确边框和阴影。
- 分组标题不拼接“已停用”长文本；使用状态点和辅助标签表达。
- 当前选中分组使用左侧强调线、浅色底和数量徽标。
- 条目列表不添加额外常驻分组列，不缩减现有卡片内文宽度。
- 图标按钮使用现有 lucide 图标，熟悉图标不再使用长文本矩形按钮。

## 组件边界

- `AdminRunningHubGroupManager` 从条目 rail 的常驻布局中移出，改为抽屉内容组件。
- `AdminRunningHubWorkspace` 负责抽屉开关、焦点关闭和触发器状态展示，继续复用现有分组 mutation handlers。
- 新增必要的样式和结构约束测试，验证 manager 不再位于 list body 之前的常驻 grid 流，并验证抽屉遮罩、固定层级和关闭语义。

## 非目标

- 不改变 API、分组数据模型、权限判断或条目过滤语义。
- 不新增移动端专用布局；现有响应式规则不主动扩展。
- 不引入新的全局状态管理库。

## 验收

- 1920×1080 下，条目 rail 中标题、备注、Schema 摘要和底部状态不被分组 UI 覆盖或压缩。
- 打开抽屉后，背景条目不可点击；关闭后恢复原有条目选择行为。
- 全部、命名分组、未分组筛选结果与现有行为一致。
- 新建、启用/停用、删除分组操作仍可用。
- 组件约束测试、Admin 类型检查和构建通过。
