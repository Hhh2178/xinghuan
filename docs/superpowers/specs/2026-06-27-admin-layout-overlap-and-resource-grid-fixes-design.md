# Admin 后台布局重叠与资源卡片网格修复设计

**日期：** 2026-06-27  
**范围：** `API 设置`、`组织与治理`、`资源与内容 / 公共资源`  
**状态：** 已确认设计，待进入实施  

---

## 1. 背景

当前 gray 版本在后台前端仍存在三组高优先级问题：

1. `API 设置` 顶部仍保留一块重复的说明型大面板，和分区切换区发生视觉叠压，影响点击。
2. `组织与治理` 中 `账号 / 用户组 / 权限` 页面仍存在表单横向堆叠、按钮颜色过亮、信息区被左侧创建卡压缩的问题。
3. `公共资源` 页面左侧分类 rail 过宽，右侧资源详情仍然采用单条详情式布局，导致素材预览不完整、卡片区密度低且后续扩展容易继续混乱。

用户本轮要求不是新增功能，而是完成一次针对后台核心治理页面的结构收口和交互修复。

---

## 2. 目标

本轮只解决以下目标：

1. 删除 `API 设置` 中重复且会压住分区切换的说明大板块。
2. 把 `组织与治理` 的 `新增成员` 改成竖向窄卡，释放右侧账号工作台空间。
3. 重排 `账号 / 用户组 / 权限` 相关页面中的按钮、输入框、状态块，去掉亮青大面积按钮和卡片。
4. 将 `公共资源` 改为自适应等宽卡片网格，默认折叠详情，只展开一张卡片。
5. 展开单张资源卡时，通过正常文档流向下撑开，把下面卡片整体挤下去，禁止叠层覆盖。

---

## 3. 非目标

本轮不做以下内容：

1. 不新增后台业务能力或新权限维度。
2. 不修改灰度/生产部署流程。
3. 不重做后台全部页面，只处理这次明确指出的三组页面。
4. 不重新引入 `生成库` 或恢复任何已经删除的后台 IA 条目。

---

## 4. 设计决议

### 4.1 API 设置

处理方式：

1. 删除 `统一管理接入能力` 整块说明型 band。
2. 保留页面主标题、状态条、最近刷新、AI 助手和用户信息。
3. 分区切换条直接暴露在可点击层，不允许被上层透明或半透明面板覆盖。
4. `API 设置 / RH 工作台 / AI 助手` 的切换入口仍保留，但只作为分区导航，不再嵌套在说明 hero 内。

预期结果：

1. 页面进入后第一屏直接可点分区。
2. 不再出现“板块重叠导致点不到下面分区”的情况。

### 4.2 组织与治理

#### 账号页

处理方式：

1. 左侧 `新增成员` 改成固定宽度的竖向卡片。
2. 每个字段独占一行，包含：
   - 邮箱
   - 名称
   - 角色
   - 所属分组
   - 初始密码
   - 创建按钮
3. 右侧 `账号治理工作台` 获得更大的主区域宽度。
4. 账号行内部改为分区式布局，不再把：
   - 邮箱
   - 角色
   - 分组
   - 密码托管
   - 状态开关
   - 删除/禁用/重置
   全部挤成同一条极长横排。
5. 危险操作保留 danger 样式，但普通操作按钮统一回深底边框态。

#### 用户组页 / 权限页

处理方式：

1. 左侧 rail 保持可读，但取消大面积亮青底。
2. 当前选中态改为深底 + 边框高亮 + 白字。
3. 右侧统计卡、工具条、筛选和保存区统一成低对比深色结构。
4. 所有普通按钮、输入框、切换控件禁止再使用亮青填充大按钮。

预期结果：

1. 左侧创建卡不再压缩右侧账号区。
2. 账号、用户组、权限三个分区的视觉主次清楚。
3. 所有文字都具备稳定对比，不再出现“亮色卡片上看不清字”。

### 4.3 公共资源

处理方式：

1. 左侧分类 rail 收窄，仍保留：
   - 分类列表
   - 新增分类
   - 当前分类高亮
2. 右侧资源区改为自适应等宽卡片网格：
   - 宽屏优先 4 列
   - 中等宽度降为 3 列
   - 再窄降为 2 列
3. 每张资源卡默认只显示：
   - 素材预览
   - 资源名称
   - 展开入口
4. 参数区默认折叠。
5. 同一时间只允许展开 1 张卡片。
6. 点击新卡片展开时，自动收起旧卡片。
7. 展开区域写在卡片自身文档流里，向下撑开卡片高度，把下面卡片自然挤开。
8. 预览区继续保持完整素材显示，空白区域允许黑底补齐，不允许为了铺满卡片裁掉内容。

预期结果：

1. 卡片宽度一致。
2. 默认浏览状态密度更高、版面更干净。
3. 展开详情时不会与其他卡片互相堆叠。

---

## 5. 视觉规则

本轮继续沿用当前后台的深色体系，但补一条明确约束：

1. 亮青色只允许作为小面积强调，不允许作为大面积普通按钮填充色。
2. 普通按钮统一使用：
   - 深底
   - 浅边框
   - 白字
3. 选中态采用：
   - 深底
   - 青绿色描边
   - 白字
4. danger 操作单独保留红色体系。
5. 统计芯片、标签和状态 pill 可以保留青色/绿色/橙色语义，但不允许与主操作按钮混淆。

---

## 6. 响应式规则

### 6.1 账号治理

1. 左侧新增成员卡采用固定上限宽度。
2. 当可用宽度不足时，页面优先从双栏降为上下结构，而不是继续硬挤右侧账号区。

### 6.2 公共资源

1. 资源卡片区采用 `repeat(auto-fit / auto-fill)` 类自适应网格策略。
2. 卡片最小宽度保持一致，保证列数自动变化时视觉稳定。
3. 卡片展开内容不使用绝对定位浮层。

## 8. 验收标准

### 8.1 API 设置

1. `统一管理接入能力` 大板块被移除。
2. 分区切换区可以直接点击，不被上层遮挡。

### 8.2 组织与治理

1. `新增成员` 为竖向卡片，一项一行。
2. 账号管理区域宽度明显恢复。
3. 普通按钮不再出现亮青大面积填充。
4. 用户组页和权限页文本清晰可读，无大面积亮底压字。

### 8.3 公共资源

1. 左侧分类 rail 宽度缩小。
2. 右侧资源区为自适应等宽卡片网格。
3. 默认仅显示预览和名称。
4. 详情区默认折叠。
5. 同时只允许展开 1 张卡片。
6. 展开时卡片向下撑开，不与下方内容堆叠。
7. 资源预览保持完整比例展示。

---

## 9. 风险控制

1. 公共资源从“单详情区”改到“网格 + 单卡展开”后，需要重点检查：
   - 选中态
   - 保存/删除操作是否仍能准确命中当前资源
2. 账号管理区重排后，需要重点检查：
   - 禁用/启用
   - 密码重置
   - 分组切换
   - 创建用户
3. 所有修复完成后，至少要重跑：
   - 构建
   - 后台相关契约
   - 本地页面验收
