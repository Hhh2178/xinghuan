# 系统发布任务窗口与最终状态时间设计

**日期：** 2026-07-14
**状态：** 已确认，待编写实施计划
**范围：** 后台 `系统与发布 > 任务` 监控页

## 1. 决策

任务监控页最多展示最近活动的 2,000 条任务记录。历史任务继续保留在数据库中，本功能不删除、不归档旧任务。

任务首次进入最终状态时，记录一个稳定的 `finalizedAt` 时间。任务成功、失败或取消时，任务表格展示该最终状态时间；仍在执行中的任务不展示最终状态时间。

## 2. 目标

- 避免历史任务持续增长后拖慢系统发布页面。
- 明确提示管理员当前页面只展示最新 2,000 条记录。
- 区分任务最终状态发生时间与后续补日志、补诊断导致的更新时间。
- 保持现有能力、Provider、状态筛选、分页、任务详情、重试、取消和审计行为。
- 保持 PostgreSQL 与本地文件模式的一致行为。

## 3. 不在本次范围

- 删除、归档或清理旧任务记录。
- 修改 Worker 保留策略、输出素材保留策略、任务重试策略或审计日志保留策略。
- 新增面向用户的任务状态。
- 修改 Provider 模型拉取、导入或手动创建模型流程。

## 4. 数据约定

### 4.1 时间字段

`createdAt` 继续表示平台接收任务的时间，`updatedAt` 继续表示任务记录最后一次被修改的时间。新增可为空的 `finalizedAt`，表示任务第一次进入最终状态的时间。

最终状态包括 `completed`、`succeeded`、`success`、`failed`、`cancelled`、`canceled`，统一通过现有状态处理逻辑识别。首次进入最终状态时写入 `finalizedAt`；之后即使补写日志、诊断或其他信息，也不能改写它。

迁移前的历史终态记录没有 `finalizedAt` 时，列表接口使用其 `updatedAt` 作为展示兼容值，但读取操作不回写数据库。

### 4.2 存储

- PostgreSQL：为 `xh_tasks` 增加可为空的 `finalized_at timestamptz` 字段，并增加支持最近活动任务查询的索引。
- 本地文件模式：在现有任务 JSON 结构中持久化可选 `finalizedAt`。
- Repository 映射、列表摘要、任务详情和任务生命周期辅助函数一致暴露该字段。

## 5. 列表窗口与接口

先确定固定展示窗口，再执行筛选和分页：

1. 按 `updated_at desc, created_at desc, id desc` 选取最近活动的 2,000 条任务。
2. 在这固定的 2,000 条窗口内执行能力、Provider 和状态筛选。
3. 对筛选结果继续使用现有分页。

因此筛选不会查询早于当前 2,000 条窗口的任务。接口新增返回：

- `total`：当前窗口内匹配筛选条件的记录数。
- `windowLimit`：固定为 `2000`。
- `windowSize`：筛选前窗口实际包含的记录数。
- `truncated`：存在更早记录未进入窗口时为 `true`。

任务列表摘要继续不返回 `payload`、`result`、`logs` 等重字段。

## 6. 后台交互

任务监控保留当前表格和分页控制。在表格上方持续显示一条窗口说明：

- 任务总数不超过 2,000 条时：`显示全部 N 条最近任务`。
- 存在更早任务未展示时：`仅显示最近 2,000 条任务记录`。

在 `状态` 后新增固定宽度的 `最终状态时间` 列：

- 成功终态：显示本地化日期时间，使用成功状态样式。
- 失败或取消终态：显示本地化日期时间，使用失败或取消状态样式。
- 排队、执行、重试或其他非终态：显示弱化的 `--`。

该列不换行，悬停可查看精确时间。较窄屏幕下沿用现有表格横向滚动，不压缩或遮挡相邻列。

### 6.1 单条任务的信息密度

任务监控列表用于快速扫描，不承担展示完整参数、完整日志或长文本的职责。每条任务记录遵循以下限制：

- 每个表格单元格默认单行显示，单元格内容使用省略号截断，悬停展示完整原文。
- `任务` 列仅显示任务标题；能力、Provider、模型等不重复拼接进标题。
- `Provider` 列仅显示 Provider 名称，`模型` 列仅显示模型显示名称或模型 ID，二者不得拼接为长路径。
- `发起账号` 列显示账号名称，邮箱仅在悬停或详情中查看。
- `日志` 列只显示最新一条简短状态摘要，完整日志、结果和请求参数必须通过既有详情入口查看。
- 行高保持稳定，不因长名称、错误文本或模型 ID 增长；窄屏仍使用表格横向滚动，不把多列压缩成多行堆叠。

## 7. 生命周期规则

- 新建的排队或执行中任务：`finalizedAt = null`。
- 成功、失败、超时终态化、取消和 Worker 终态恢复：仅在字段为空时写入。
- 重试会创建新任务，新任务 `finalizedAt = null`；原任务保留自身的最终状态时间。
- 管理员编辑任务信息时不能手动覆盖最终状态时间。

## 8. 测试与验收

自动化测试必须覆盖：

1. 列表不会返回最新 2,000 条窗口外的记录，且 `truncated` 正确。
2. 分页与所有既有筛选只在该窗口内生效。
3. PostgreSQL 列表查询不加载任务的 `payload`、`result`、`logs`。
4. 任务变为成功、失败或取消时只写入一次 `finalizedAt`。
5. 后续任务写入或日志写入不能改写既有 `finalizedAt`。
6. 没有 `finalizedAt` 的历史终态任务能正确显示 `updatedAt` 兼容值。
7. 后台表格在支持的桌面分辨率下展示窗口说明和最终状态时间列，且无文字溢出或元素重叠。
8. 长任务名、Provider、模型、账号和日志摘要不会改变行高或导致跨列文字堆积，完整内容可通过悬停或详情入口读取。

## 9. 发布策略

数据库迁移为新增字段，向后兼容，不对旧任务做破坏性回填。先灰度发布，验证任务列表分页，以及至少一条成功任务和一条失败任务的最终状态时间，再进行视觉验收和正式发布。
