# 素材生命周期管理与 Production 完整迁移设计

## 目标

验证现有生成素材三天清理是否真实生效，补齐资源库持久化与物理文件删除边界，在 Admin 运行参数中增加可编辑的素材保留天数，并于 2026-08-05 18:30（Asia/Shanghai）将旧服务器 Production 的完整业务数据安全替换到新服务器 Production。

## 已确认约束

- 开发仓库继续使用源码链路；保留天数配置不通过手写源码常量驱动。
- 新服务器 Production 初始保留天数为 15 天，可由 Admin 修改。
- 资源库中的收藏、分类、仍被画布/任务引用的资源不因临时产物清理而删除。
- 旧服务器 Production 的数据库、资源库、画布、项目、生成记录及对应文件完整迁移到新服务器 Production。
- 新服务器现有 Production 数据先完整备份，再执行覆盖；旧服务器保持不变作为回滚来源。
- 密钥不进入 Git、日志、聊天或迁移文档；Redis 临时队列和登录会话不迁移，避免重复执行和会话串用。
- 定时任务到点自动执行，不等待人工确认；执行前必须完成备份和只读预检。

## 方案

### 生命周期参数

在 `xh_system_settings` 增加 `material_lifecycle_settings` JSON 字段，保存 `outputRetentionDays`、revision 和 updatedAt。读取顺序为数据库参数、环境变量兼容回退、代码默认值 3 天。Worker 和 output-prune timer 统一通过共享读取函数获得有效值。

### Admin 管理层

沿用 `/api/admin/system` 与 `/api/admin/queue-settings` 的 revision/audit 模式，在运行参数页加入“素材生命周期”面板。面板显示当前值、清理范围、最近清理结果和保存状态；输入限制为 1–3650 天。布局把任务并发与素材生命周期分成两个并列配置区，并保留环境和版本摘要。

### 资源库删除

删除 API 在 ownership/revision 校验通过后，在事务内删除 `xh_assets` 记录；根据 `metadata.fileUrl/fileRel` 解析到 owner-scoped 文件路径，只有无其他资源引用且不属于生成任务仍需保留的文件才物理删除。删除动作写入审计，路径解析拒绝越界路径。

### 完整迁移

一次性迁移脚本按以下阶段执行：锁定目标、备份新服务器数据库和共享文件、导出旧服务器 Production 数据库、停止新服务器 API/Worker、恢复数据库、同步旧 Production 持久化文件、写入 15 天参数、启动服务、执行状态/权限/文件一致性检查。任一阶段失败即停止，不清理快照，不切换旧服务器。

## 验收标准

- 清理 dry-run 能显示实际保留天数和候选数量；apply 只删除符合规则的临时生成物。
- 资源库删除后数据库记录消失，未被其他资源引用的物理文件消失，共享文件仍保留。
- Admin 修改 15 → 20 天后，API、Worker 和清理器读取同一值。
- 新服务器 Production 迁移后数据统计、权限 readiness、API/Worker、资源库记录和文件清单与旧服务器导出一致。
- 定时任务只执行一次，迁移日志和失败码可追踪。
