# 后台治理重构设计方案

**日期：** 2026-06-26  
**范围：** 用户 / 用户组 / 权限 / 公共资源管理后台重构  
**状态：** 已完成诊断，待进入实施计划

---

## 1. 背景

当前后台已具备用户、用户组、权限策略、公共资源管理的首版能力，但近期灰度验收暴露出三类关键问题：

1. 用户组创建在中文业务场景下出现 `用户组 ID 已存在` 报错，且创建失败后 UI 未给出正确的局部反馈。
2. 公共资源管理页虽然已有入口和基础 CRUD，但未达到既定的卡片化预览治理方案，素材预览与管理结构仍偏表单列表。
3. 用户 / 权限后台的视觉层级、信息架构、滚动区域与状态表达不稳定，已经影响日常治理效率，并出现标题压缩、颜色抢焦点、局部滚动陷阱等问题。

本方案用于统一后续修复与重做标准，避免继续出现“功能存在，但实现形态与计划不一致”的偏差。

---

## 2. 现状诊断

### 2.1 用户组创建报错

后端创建用户组接口当前会用 `safeSlug(body.id || name, fallback)` 生成分组 ID。  
该清洗逻辑仅保留英文字母、数字、下划线和连字符，中文名称会退化成高度重复的短 slug。

结果：

- 中文分组名即使显示不同，也可能生成相同 ID。
- 后端在落库前检测到相同 ID 后直接抛出 `用户组 ID 已存在`。
- 前端创建动作走的是全局 `mutate()` 错误链路，导致整个后台顶部出现全局错误横幅，而不是仅在“创建用户组”表单中提示。

诊断结论：

- 这是后端真实主键生成策略缺陷，不是前端假报错。
- 同时也是错误展示层级错误，局部表单错误被升级成全局系统错误。

### 2.2 公共资源管理后台偏离计划

公共资源后台已具备：

- 分类读取、新增、重命名、删除
- 本地文件上传入口
- 素材列表、基础编辑、删除

但当前页面仍采用“左侧分类 + 右侧横向列表行”的结构。每一条资源都把：

- 预览
- 标题/分类/标签/备注
- 文件信息
- 操作按钮

挤在同一行完成。

结果：

- 预览区过小，只能作为缩略占位，不能承担素材治理主视觉。
- 视频、音频没有真正的查看型预览，只是图标占位。
- 一旦字段、按钮继续增加，就会继续发生横向挤压。
- 页面虽然能管数据，但不像素材后台，更像临时列表编辑器。

诊断结论：

- 当前实现是功能首版，不是计划目标版。
- 问题不在“没有页面”，而在“信息架构和交互深度没有达到方案要求”。

### 2.3 用户 / 权限后台 UI 结构失衡

当前用户后台将 `账号 / 用户组 / 权限 / 会话` 四块能力装入同一工作台，并通过顶部切换页签切分。该方向本身成立，但具体实现存在以下问题：

1. 顶部 hero 文本、状态按钮、指标 chips 同屏竞争，缺少稳定的响应式降级规则。
2. 权限页左侧分组卡片过亮、过大，右侧编辑器反而主次不清。
3. 高亮色在选中态、允许态、成功态之间重复使用，导致视觉重点混乱。
4. 组列表、分类列表虽然设置了滚动，但没有统一滚动边界设计，易出现“小块区域才能滚动”的可用性问题。
5. 多处按钮组仅靠 `wrap` 被动换行，缺少按钮优先级、宽度约束和布局收束规则。

诊断结论：

- 当前不是个别组件丑，而是页面骨架、状态色系统、滚动策略和响应式规则同时需要重整。

---

## 3. 设计目标

本轮后台治理重构需要同时达成五个目标：

1. **稳定性**  
   修复用户组创建主键冲突，建立适合中文业务场景的 ID 策略。

2. **治理清晰度**  
   用户、用户组、权限、会话、公共资源都要形成清晰工作区，不再互相挤压。

3. **素材可读性**  
   公共资源后台必须能让管理员快速看清素材全貌，而不是只看见小缩略图或图标。

4. **权限可控性**  
   分组权限治理要保持“未开放即隐藏”的前台策略，同时后台要让限制项一眼可扫、一眼可改。

5. **防回归**  
   明确禁止文字溢出、颜色混乱、错误提示越级、局部滚动陷阱等问题再次进入灰度。

## 4. 方案对比

### 方案 A：在现有页面上继续补丁式修样式

优点：

- 开发速度快
- 短期可缓解最明显的溢出问题

缺点：

- 不能解决公共资源后台的结构问题
- 不能解决权限页的视觉主次混乱
- 后续继续加功能时还会回到“越补越挤”的状态

结论：

- 不推荐作为主方案，只适合应急热修。

### 方案 B：局部重构公共资源页和权限页，用户页仅小修

优点：

- 成本中等
- 能解决本轮最明显的问题

缺点：

- 用户页 hero、分组管理、全局错误提示这些问题仍会残留
- 用户 / 权限体系的体验仍不统一

结论：

- 可作为预算受限方案，但不满足“全面重做”的目标。

### 方案 C：按治理域做完整后台重构

优点：

- 能同时修复功能缺陷、布局缺陷与视觉规范问题
- 能为后续继续增加资源权限、RH 权限、节点权限留出稳定空间
- 可把“隐藏未开放资源”的策略彻底体现在后台配置体验中

缺点：

- 需要拆成多批实施
- 需要同步补文档、验证和灰度验收

结论：

- **推荐采用方案 C。**

## 5. 最终设计

### 5.1 用户组主键与错误链路重做

#### 主键策略

用户组创建不再直接使用分组名称 slug 作为唯一主键。

改为：

- `id` 使用系统生成的稳定唯一值，形如 `group-<timestamp>-<random>`
- `name` 继续作为业务展示名
- 名称唯一性单独校验
- slug 如需保留，仅作为辅助检索或未来友好路径，不参与主键唯一性

#### 前端错误反馈

- 创建用户组失败时，仅在“新建用户组”卡片内显示错误
- 不再把这类局部表单错误挂到后台顶部全局错误横幅
- 创建成功后：
  - 清空表单
  - 刷新分组列表
  - 把新建分组滚动到可见区域

### 5.2 用户治理工作台重做

用户治理页继续保留四个一级区块：

- 账号
- 用户组
- 权限
- 会话

但统一采用“工作台分区”而不是“堆满信息的长页卡片”。

#### 账号区

结构：

- 顶部：创建成员面板
- 下方：全宽账号表

重点字段：

- 邮箱
- 名称
- 所属组
- 备注
- 角色
- 启用状态
- 当前密码可用性
- 重置密码

要求：

- 表格列宽设定上下限
- 长邮箱、省略展示但支持 hover 全量
- 行内编辑区不允许挤压相邻列

#### 用户组区

结构：

- 左侧：新建分组面板
- 右侧：分组卡片墙

每张卡片展示：

- 分组名称
- 分组说明
- 成员数量
- 已限制公共资源数
- 已限制 RH 条目数
- 已限制节点数
- 排序值

交互：

- 卡片默认展示摘要，不直接把所有输入框常驻展开
- 点击“编辑”后进入卡片编辑态，或右侧/弹层详情编辑态
- 删除按钮仅在无成员时可用

目标：

- 分组区应支持大量分组
- 不再依赖窄小滚动条查看全部分组

#### 权限区

结构：

- 左侧：分组选择轨道
- 右侧：权限治理工作区

右侧结构：

1. 顶部当前组选情摘要
2. 关键统计条带
3. 四个权限子区 Tab
   - 公共资源
   - RH AI 应用
   - RH 工作流
   - 节点能力
4. 内容区
5. 底部固定保存条

内容区规则：

- 公共资源优先支持“分类 + 条目”双层限制
- RH 应用与工作流按目录条目列出
- 历史缺失 ID 必须保留显示，不自动吞掉

保存条规则：

- 固定在底部
- 只表达三种状态：
  - 未修改
  - 有未保存改动
  - 保存中 / 已保存

#### 会话区

结构：

- 单独展示活跃会话与已撤销会话
- 支持强制下线
- 与用户组和权限编辑完全解耦

### 5.3 公共资源管理后台重做

公共资源后台改为“素材治理工作台”。

#### 页面结构

1. 顶部总览区
   - 页面标题
   - 资源类型切换
   - 搜索
   - 上传按钮
   - 当前资源数量摘要

2. 左侧分类区
   - 分类列表
   - 新增分类
   - 重命名分类
   - 删除分类

3. 右侧资源区
   - 资源卡片网格
   - 支持图像 / 视频 / 音频 / 素材集 / 姿势 / 工作流

#### 卡片结构

卡片采用上下结构：

- 上半区：预览容器
- 下半区：参数与管理区

预览容器规则：

- 固定最大显示框
- 黑底补边
- 素材必须完整展示
- 使用 `contain`，禁止裁切主体

不同素材的预览：

- 图像：直接完整预览
- 视频：显示封面帧，支持点开播放预览
- 音频：显示音频占位与时长/类型信息，支持点开试听
- 其他素材：显示标准化图标与类型信息

管理区展示：

- 标题
- 分类
- 标签
- 备注
- mime / 文件大小 / 更新时间
- 查看
- 编辑
- 删除

#### 完整预览能力

每张卡片都提供“查看完整素材”动作。

预览弹层规则：

- 最大容器尺寸固定
- 素材完整展示
- 不要求铺满全屏
- 图像 / 视频 / 音频都使用统一预览框架

### 5.4 颜色与视觉层级规范

后台继续保持科技黑 + 青绿色系，但必须重建状态优先级。

颜色使用规则：

- 主强调色：仅用于当前选中和主操作
- 成功色：仅用于保存成功、就绪状态
- 警示色：仅用于禁用、限制、风险提示
- 危险色：仅用于删除、不可逆操作、系统错误

禁止：

- 允许态、选中态、成功态同时使用同一亮色
- 左侧选择卡片比右侧主编辑器更抢眼
- 将所有统计 chip 都设计成同等高亮

文字层级规则：

- 页面主标题：18-24px
- 区块标题：16-18px
- 描述文案：12-14px
- 卡片 meta：11-12px

### 5.5 响应式与防溢出规则

后台重构必须内建以下硬规则：

1. 所有标题和描述默认允许换行，不允许被裁切。
2. 所有按钮组支持自动换行，换行后保持对齐和间距，不允许压缩预览区。
3. 所有 chips / pills 允许折行，不允许把父容器撑爆。
4. 左侧列表区的滚动必须是完整面板滚动，不允许只剩一小块局部可滚动区域。
5. 表格和卡片中长文本必须有：
   - 最大宽度
   - 省略策略
   - hover/查看完整内容能力
6. 资源预览容器统一设置尺寸边界，禁止不同素材撑坏卡片。

## 7. 验收标准

本轮重做完成后，至少满足以下验收项：

### 7.1 用户组创建

- 中文分组名可连续创建，不再出现误报 `用户组 ID 已存在`
- 创建失败时只在局部表单提示错误
- 创建成功后列表立即可见新分组

### 7.2 公共资源管理

- 后台资源以卡片结构展示
- 图像素材完整显示
- 视频素材可预览并完整查看
- 音频素材可试听或进入完整预览
- 资源卡片的操作按钮在窄宽度下自动换行，不溢出

### 7.3 用户 / 权限后台

- 顶部标题、副标题、指标在常见桌面宽度下无裁切
- 左侧分组轨道可完整浏览大量分组
- 权限页高亮层级清晰，选中态与允许态不混色
- 保存条固定明确，不出现“改了但不知道有没有保存”的状态

### 7.4 防回归

- 1280、1440、1920 宽度下无文本溢出
- 不出现局部小滚动陷阱
- 不出现按钮文字压缩到不可读
- 不出现预览图被裁切而看不清主体

## 8. 实施批次建议

建议按四批推进：

### 批次 1：用户组创建链路修复

- 修复后端用户组 ID 生成策略
- 调整前端局部错误反馈

### 批次 2：公共资源后台卡片化改造

- 重构公共资源页骨架
- 增加资源卡片与完整预览能力
- 统一图片 / 视频 / 音频预览逻辑

### 批次 3：用户 / 权限后台重做

- 重做 hero、统计、分组卡片、权限工作区
- 收口颜色与状态表达
- 收口滚动区与响应式规则

### 批次 4：防回归验收

- 多宽度 UI 检查
- 权限与资源联动验证
- 灰度前专项验收

---

## 9. 风险与注意事项

- 不能只改 CSS 而不改结构，否则公共资源后台问题会反复出现。
- 用户组 ID 修复需要考虑 file / postgres 两种 auth storage 路径一致性。
- 前台“未开放即隐藏”的策略必须保持不变，后台只调整治理体验，不反向改成前台显示拒绝。
- 对热点文件改动时，应同步记录拆分落点，避免继续把 `admin-users-panel.tsx`、`admin-permissions-panel.tsx`、`admin-public-resources-panel.tsx` 推成更大的超级文件。

---

## 10. 本方案决议

本轮采用：

- **完整治理域重构方案（方案 C）**

不采用：

- 仅样式补丁
- 仅局部小修

后续实施必须以本方案为准，并在进入编码前拆出正式实施计划。
