# 星幻无限画布 Admin 后台 UI 页面 PRD

**文档日期：** 2026-06-27  
**交付对象：** UI / UX 设计师  
**文档目标：** 明确新版 Admin 后台需要设计哪些页面、每个页面包含哪些功能区、每个功能区需要支持哪些交互和状态。  
**设计范围：** Admin 独立后台，不包含前台画布工作区的具体设计。  
**设计方向：** 科技感可视化运营后台 + 参数配置控制台 + 权限治理系统。  

---

## 1. 项目说明

星幻无限画布是公司内部节点式 AIGC 创作平台。Admin 后台不是普通的数据管理后台，而是整个平台的运营和治理中心。管理员需要在这里完成：

- 查看平台健康状态和任务运行情况。
- 管理 Provider、模型、RunningHub 应用和工作流。
- 管理公共资源、生成内容、公告和内容分类。
- 管理账号、用户组、权限、会话、审计和用量。
- 管理系统参数、任务队列、环境同步和发布状态。

新版后台 UI 需要避免旧后台中出现的问题：

- 页面只是功能堆叠，没有运营总览感。
- 表格、卡片、按钮在内容变多后挤压变形。
- 分类、分组、按钮区局部滚动体验差。
- 状态颜色混乱，选中、成功、警告、危险不清晰。
- 资源预览不完整，图片和视频主体被裁切。
- 权限能力分散，管理员难以判断某个组到底能看到什么。

---

## 2. 设计目标

### 2.1 产品目标

设计一套完整的新 Admin 后台，使其具备以下能力：

1. 作为平台运营驾驶舱，能快速看到健康、用量、风险和变更。
2. 作为能力配置中心，能管理所有生成模型、RH 应用、RH 工作流和节点能力。
3. 作为资源内容中心，能管理公共素材、生成库、公告、分类和标签。
4. 作为组织治理中心，能管理账号、分组、权限、会话、审计和用量。
5. 作为系统发布中心，能管理任务队列、运行参数、环境同步和发布状态。

### 2.2 体验目标

1. 管理员进入后台后，第一眼知道系统是否正常。
2. 页面信息层级清晰，主操作、辅助操作、危险操作区分明显。
3. 所有对象都能从列表进入详情，不靠弹窗堆大量字段。
4. 所有配置修改都能明确看到未保存、保存中、保存成功、保存失败、冲突和实际生效状态。
5. 设计上必须预留未来新增功能的位置，不靠不断加菜单解决扩展。

### 2.3 视觉方向边界

本 PRD 不要求设计师立刻输出最终视觉风格，但需要按以下方向设计：

- 面向内部生产工具，避免营销页和装饰性大图。
- 整体可以偏科技黑、青绿色强调和数据可视化感。
- 色彩用于表达层级和状态，不做无意义高亮。
- 卡片、表格、仪表、参数面板需要统一设计语言。
- 数据密集型页面优先保证可扫读、可比较、可操作。

## 3. 用户角色

### 3.1 超级管理员

负责系统级配置、账号权限、Provider、模型、RH 条目、环境同步和发布状态。

核心任务：

- 配置新 Provider 和模型。
- 管理用户组和权限。
- 查看系统健康和发布状态。
- 处理高风险告警。

### 3.2 运营管理员

负责日常运营、任务观察、用量统计和公告发布。

核心任务：

- 查看用量趋势。
- 查看任务成功和失败情况。
- 发布公告。
- 查看账号和分组使用情况。

### 3.3 内容管理员

负责公共资源、生成内容和标签分类。

核心任务：

- 上传公共资源。
- 分类管理资源。
- 查看素材完整预览。
- 将生成结果沉淀为公共资源。

### 3.4 技术运维

负责系统运行、队列、并发、Redis、数据库、Worker 和环境同步。

核心任务：

- 查看系统健康。
- 调整任务并发参数。
- 查看队列积压。
- 处理环境同步冲突。

## 5. 全局框架页面

## 5.1 后台 Shell

### 页面目的

提供后台统一导航、环境状态、全局搜索、告警、管理员账号操作和 AI 助手入口。

### 页面布局

- 左侧一级导航。
- 顶部状态栏。
- 中央主工作区。
- 右侧后台 AI 助手，可展开和收起。

### 左侧导航需要展示

- 工作域图标。
- 工作域名称。
- 当前选中态。
- 工作域内未处理告警数量，可选。
- 折叠态。

### 顶部状态栏需要展示

- 当前环境：gray、production、local。
- 当前系统版本。
- API 连接状态。
- 全局搜索入口。
- 告警中心入口。
- AI 助手开关。
- 当前登录管理员邮箱。
- 退出登录按钮。

### 关键状态

- 正在校验登录。
- 未登录。
- 非管理员，无权限进入。
- API 已连接。
- API 断开。
- 全局加载中。
- 存在系统级错误。

### 设计要求

- 左侧导航文字不能挤压。
- 顶部状态栏在窄宽度下需要自动收纳次要信息。
- 管理员邮箱过长时需要省略，但可查看完整邮箱。
- AI 助手展开时不能把主页面挤压到不可用。

- 每条结果的主标题。

### 交互

- 支持点击结果进入详情。

### 状态

- 搜索中。
- 有结果。

- 搜索失败。

- 简短说明。

## 6. 运营总览

## 6.1 运营总览首页

### 页面目的

这是后台第一屏。设计师需要把它设计成平台运营驾驶舱，让管理员快速判断平台是否正常。

### 用户任务

- 查看当前环境和系统健康。
- 查看今日任务成功数和失败数。
- 查看图像、视频、LLM、RH 的使用趋势。
- 查看队列是否积压。
- 查看当前最重要的风险。
- 从总览跳转到具体处理页面。

### 页面区块

#### 1. 环境健康条

展示内容：

- 当前环境。
- 当前版本。
- API 状态。
- 数据库状态。
- Redis 状态。
- Worker 状态。
- 最近更新时间。
- 活动告警数。

交互：

- 点击数据库状态进入系统健康数据库区。
- 点击 Redis 状态进入系统健康 Redis 区。
- 点击 Worker 状态进入系统健康 Worker 区。
- 点击告警数打开告警中心。

#### 2. 核心 KPI

展示指标：

- 今日成功任务。
- 当前排队任务。
- 当前运行任务。
- 24h 失败任务。
- 启用 Provider。
- 启用模型。
- 启用 RH 条目。
- 公共资源数量。
- 活跃会话。

交互：

- 每个指标点击后进入对应列表。
- 指标需要显示相对昨日或 7 日均值的变化。

#### 3. 成功用量趋势

展示内容：

- 最近 7 天或 30 天任务成功趋势。
- 图像、视频、LLM、音频、RH AI 应用、RH 工作流分能力展示。

交互：

- 支持切换时间范围。
- 点击某能力进入用量分析并自动筛选。

#### 4. 能力占比

展示内容：

- 图像占比。
- 视频占比。
- LLM 占比。
- 音频占比。
- RH AI 应用占比。
- RH 工作流占比。

设计要求：

- 适合作为数据可视化模块。
- 必须保留数值和百分比，不只显示图形。

#### 5. 队列运行状态

展示内容：

- 图片队列深度。
- 视频队列深度。
- 音频队列深度。
- RH 平台窗口占用。
- 实际生效并发。
- Worker 数。
- 槽位数。

交互：

- 点击队列进入任务队列页。
- 点击并发进入运行参数页。

#### 6. 风险和待处理

展示内容：

- 失败趋势告警。
- requestId 覆盖率告警。
- revision 冲突告警。
- Provider 探测失败。
- 环境同步冲突。

交互：

- 点击进入告警详情或对应模块。

#### 7. 最近变更

展示内容：

- 最近账号变更。
- 最近权限变更。
- 最近 Provider / 模型变更。
- 最近 RH 条目变更。
- 最近资源变更。
- 最近公告发布。
- 最近系统参数变更。

交互：

- 点击进入审计日志并定位该记录。

### 页面状态

- 全部健康。
- 有警告。
- 有严重风险。
- 数据加载中。
- 部分数据加载失败。
- 当前没有成功任务。

### 设计验收

- 第一屏必须能看到健康、KPI、用量和风险。
- 不允许总览变成普通表格堆叠。
- 所有数据图表都必须有下钻入口。

### 页面布局

- 左侧 Provider 列表。
- 中间 Provider 配置表单。
- 右侧 Provider 详情 Inspector。
- 下方关联模型区域。

### 左侧 Provider 列表

字段：

- Provider 名称。
- 协议。
- 启用状态。
- Base URL 摘要。
- Key 是否配置。
- 最近探测状态。

操作：

- 搜索 Provider。
- 新增 Provider。
- 选择 Provider。

### 中间配置表单

字段：

- Provider ID。
- 名称。
- Base URL。
- 协议选择。
- API Key 输入。
- 启用状态。
- 备注。

按钮：

- 保存。
- 验证地址。
- 拉取模型。
- 删除 Provider。
- 发送到 AI 助手。
- AI 分析配置。

### 右侧 Inspector

展示：

- Provider 基础信息。
- Key 配置状态。
- 最近探测结果。
- 关联模型数量。
- RH 条目数量。
- 最近任务成功 / 失败。
- 最近审计记录。

### 弹窗

删除 Provider 确认弹窗需要展示：

- Provider 名称。
- 关联模型数量。
- 关联 RH 条目数量。
- 可能影响画布节点选择。
- 删除不可自动恢复提示。

### 状态

- 未保存修改。
- 保存中。
- 保存成功。
- 保存失败。
- 未配置地址。
- 未配置 Key。
- 探测中。
- 探测成功。
- 探测失败。

### 设计验收

- API Key 不能完整明文展示。
- Base URL 很长时不能撑爆列表。
- 删除操作必须是危险操作样式。

- 最近更新时间。

## 13. 权限设计要求

### 后台访问

第一阶段只有管理员可以进入后台。

### 前台隐藏规则

普通用户无权限时，前台直接隐藏：

- 公共资源。
- RH AI 应用。
- RH 工作流。
- 节点能力。

### 后台展示规则

后台权限页可以显示允许和禁用，但必须清楚告诉管理员：禁用后的前台效果是隐藏，不是显示拒绝。

### 未来角色预留

设计需要预留以下角色空间：

- 超级管理员。
- 运营管理员。
- 内容管理员。
- 技术运维。
- 只读管理员。

---

## 14. 设计红线

以下问题不允许出现在设计稿中：

- 文字溢出容器。
- 按钮文字被压缩到不可读。
- 表格字段把页面撑爆。
- 卡片因为动态内容高度失控。
- 资源预览裁切主体。
- 分类或分组只能在很小的局部区域滚动。
- 页面出现无意义双滚动条。
- 成功、选中、警告、危险使用同一种高亮颜色。
- 删除、发布、同步等高风险操作没有确认。
- 无权限内容在前台显示拒绝状态。

## 16. 验收标准

设计稿通过评审需要满足：

1. 所有页面都有明确布局和功能区。
2. 每个页面都有主要操作路径。
3. 每个高风险操作都有确认设计。
4. 每个配置类页面都有保存状态设计。
5. 资源类页面能完整预览图片、视频、音频。
6. 权限页能清楚表达组、资源、RH、节点之间的关系。
7. 总览页能表达健康、用量、队列、风险。
8. 用量页能表达组、账号、模型、RH 条目的统计关系。
9. 系统页能表达数据库、Redis、Worker、队列和告警。
10. 设计稿没有文字溢出、按钮挤压、卡片撑爆和小滚动陷阱。
