## 1. 背景

当前 Admin 后台已经具备用户、Provider、模型、RunningHub、公共资源、公告、任务、审计、系统观测、环境同步和 AI 助手配置等能力，但页面组织仍以“平铺菜单 + 单页堆叠”为主。近期围绕公共资源、用户权限、审计统计、RH 条目治理的连续迭代说明：后台已经不再是简单配置页，而是公司内部 AIGC 平台的运营中枢。

用户新的目标是把后台升级为“可视化仪表 + 参数治理控制台”的形态，类似大数据运营后台：既能快速看到运行态、用量、风险和资源分布，也能下钻到具体账号、分组、模型、公共资源、RH 应用、工作流、节点能力和环境同步配置。

本方案暂不设计具体视觉风格，不输出最终 UI 皮肤；重点定义：

- 后台整体层级
- 各页面职责
- 当前功能如何保留与重组
- 后续新增功能如何挂载
- 参数、权限、审计、可视化的交互逻辑
- 防止文字溢出、颜色混乱、局部滚动陷阱的结构规则

## 2. 现有能力清单

### 2.1 当前入口

现有后台导航包括：

- 总览
- 用户
- API 设置
- RH 工作台
- 公共资源
- AI 助手
- 公告
- 任务
- 审计
- 系统
- 环境同步
- 右侧后台 AI 助手

### 2.2 当前数据能力

后台前端当前已读取或操作以下数据：

- 后台总览摘要：用户、Provider、模型、任务、审计、环境、存储。
- 用户与组织：账号、用户组、会话。
- 权限策略：公共资源、RH AI 应用、RH 工作流、节点能力的分组禁用策略。
- Provider 与模型：平台地址、协议、Key 状态、模型目录、模型能力、参数 schema、测试状态。
- RunningHub：工作流、AI 应用、输入槽、参数 schema、输出定义、执行规则、Key 池、AI 分析草案。
- 公共资源：分类、图像、视频、音频、素材集、姿势、工作流资源、上传、预览、编辑、删除。
- 公告：草稿、发布、归档、删除、强提醒、置顶、弹窗、范围。
- 任务：列表、状态、发起账号、Provider、模型、日志、取消、重试、分页筛选。
- 审计与用量：审计日志、成功用量汇总、组/账号/模型/RH 条目聚合。
- 系统：数据库、Redis、队列、Worker、实际生效并发、RH 平台窗口、失败趋势、requestId 覆盖率、revision 冲突、告警。
- 环境同步：gray / production 之间用户、Provider、模型差异预览与应用。
- AI 助手配置：前台助手、后台助手、Hermes 接入、上下文授权、记忆策略。

### 2.3 当前主要结构问题

- 导航是功能平铺，缺少“运营总览、能力配置、资源内容、组织治理、系统发布”的高层分区。
- 总览页仍是基础指标卡和表格，不能承担大数据可视化运营入口。
- 任务、系统、审计的数据已经足够丰富，但分散在多个页面，缺少统一的运行态驾驶舱。
- 用户、分组、权限已经开始拆分，但仍需要纳入更大的“组织与治理中心”。
- Provider、模型、RH、节点能力之间的关系没有被统一表达成“能力目录”。
- 公共资源、公告、生成库、后续内容管理没有统一成“内容与资源中心”。
- 环境同步、release 状态、系统健康、运行配置没有统一成“系统与发布中心”。
- 右侧 AI 助手已经存在，但还没有成为全后台可上下文感知的辅助治理层。

## 3. 设计目标

### 3.1 产品目标

1. 把后台从“配置页集合”升级为“运营指挥后台”。
2. 让管理员进入后台后先看到运行态、风险、用量和关键变化。
3. 把能力配置从 Provider 单点配置，升级为 Provider / 模型 / RH 条目 / 节点能力的一体化目录。
4. 把资源管理从文件列表，升级为可预览、可分类、可授权、可审计的内容资产后台。
5. 把账号权限从账号表，升级为按组治理、按能力授权、按用量分析的组织治理后台。
6. 把系统页从长表格，升级为可观测、可调参、可发布同步的运维后台。

### 3.2 交互目标

1. 所有页面都支持先概览、再筛选、再下钻、再编辑。
2. 所有配置编辑都必须明确“未保存、保存中、已保存、冲突、实际生效”。
3. 所有危险操作都必须二次确认，并在审计中可追踪。
4. 没有开放权限的资源和能力，对普通用户直接隐藏，不显示拒绝态。
5. 后台管理员要能从数据图表直接跳转到对应对象详情。

### 3.3 扩展目标

1. 新增业务模块时，不再增加平铺菜单，而是挂到已有工作域。
2. 新增可视化指标时，优先进入统一指标系统，而不是每页自造样式。
3. 新增权限对象时，进入统一权限目录和分组策略。
4. 新增运行参数时，进入统一参数变更、预览、保存、冲突和生效验证流程。

---

## 4. 非目标

本方案不做：

- 最终视觉皮肤、颜色 token、字体细节的定稿。
- 具体 React 组件实现。
- 新数据库表结构的最终 migration 设计。
- 大屏展示的独立电视墙模式。
- 对画布前台交互的改造。

本方案会保留视觉方向约束：科技黑、青绿色强调、内部生产工具、不做营销页。

## 5. 总体信息架构

后台改为五个顶层工作域。

### 5.1 运营总览 Command Center

定位：管理员进入后台后的第一屏，统一展示平台健康、任务运行、用量趋势、异常风险、近期变更和快捷入口。

包含现有：

- 总览
- 审计成功用量的一部分
- 系统观测的一部分
- 任务运行态的一部分
- 公告 / 发布提醒摘要

### 5.2 能力配置 Capability Console

定位：管理所有“可被画布使用的生成与智能能力”。

包含现有：

- API 设置
- Provider
- 模型目录
- 模型能力标签
- RunningHub 工作台
- RH Key 池
- 节点能力目录
- AI 助手接入配置

### 5.3 资源与内容 Resource & Content Hub

定位：管理公共资源、生成资源、公告内容、素材分类、内容发布和内容权限挂点。

包含现有：

- 公共资源
- 公告
- 后续生成库后台治理
- 后续资源审查、标签、批量导入、内容版本

### 5.4 组织与治理 Governance Center

定位：管理用户、用户组、权限、会话、用量统计、审计日志和组织级策略。

包含现有：

- 用户
- 用户组
- 权限
- 会话
- 审计日志
- 成功用量驾驶舱
- 按组 / 账号 / 模型 / RH 条目统计

### 5.5 系统与发布 Ops Center

定位：管理系统运行态、队列并发、环境同步、发布状态、数据一致性和运维告警。

包含现有：

- 系统
- 任务队列参数
- 任务列表和重试取消
- 环境同步
- 数据库 / Redis / Worker 状态
- requestId 覆盖率、revision 冲突、告警
- 后续 gray / production release gate

## 6. 全局后台骨架

### 6.1 页面布局

后台采用三层骨架：

1. 顶层：全局 Shell
   - 左侧工作域导航
   - 顶部环境、搜索、告警、当前管理员、AI 助手入口
   - 主工作区

2. 中层：工作域主页
   - KPI 条带
   - 关键图表
   - 风险列表
   - 最近变更
   - 常用操作

3. 底层：对象工作台
   - 左侧对象列表或筛选轨道
   - 中间主编辑 / 表格 / 卡片区
   - 右侧详情 Inspector
   - 底部保存 / 应用 / 回滚条

### 6.2 导航规则

左侧第一层只显示五个工作域：

- 运营总览
- 能力配置
- 资源与内容
- 组织与治理
- 系统与发布

进入工作域后，在页面顶部或左侧二级导航显示模块：

- 能力配置：Provider、模型、RH 应用、RH 工作流、节点能力、AI 助手接入。
- 资源与内容：公共资源、生成库、公告、分类标签、内容权限。
- 组织与治理：账号、用户组、权限策略、会话、用量分析、审计日志。
- 系统与发布：系统健康、任务队列、任务列表、环境同步、发布状态、运行参数。

### 6.3 全局搜索

全局搜索支持搜索：

- 用户邮箱 / 备注 / 分组
- Provider / 模型
- RH catalogId / runTargetId / 标题
- 公共资源标题 / 标签 / 分类
- 任务 ID / 模型 / 发起账号
- 审计 requestId / 操作人 / 对象 ID
- 公告标题 / 版本号

搜索结果按工作域分组，点击后进入对应对象详情。

### 6.4 全局告警入口

顶部告警入口聚合：

- 任务失败趋势异常
- requestId 覆盖率异常
- revision 冲突异常
- 数据库目标不一致
- Redis / Worker 不健康
- Provider 探测失败
- RH Key 窗口耗尽或异常
- 环境同步冲突未处理

告警点击进入 Ops Center 对应下钻页。

### 6.5 后台 AI 助手

右侧 AI 助手保留，但从“聊天面板”升级为“上下文助手”：

- 能读取当前页面、当前选中对象、当前筛选条件。
- 能解释指标异常。
- 能生成配置草案。
- 能生成排障步骤。
- 能总结本次变更影响。
- 不能直接执行高风险操作，只能生成待确认操作建议。

每个页面提供“发送当前上下文给助手”动作，附件结构化包含对象 ID、状态、最近错误、相关日志摘要。

## 7. 统一交互模式

### 7.1 概览到下钻

所有图表和指标都必须可点击下钻。

例子：

- 点击“视频失败数”进入任务列表，自动筛选 capability=video、status=failed。
- 点击“某组 RH 应用用量”进入用量分析，自动筛选该组和 RH App。
- 点击“Provider 探测失败”进入对应 Provider 详情。
- 点击“某公共资源被禁用组数”进入权限策略矩阵。

### 7.2 筛选器

所有列表页使用统一筛选区：

- 搜索框
- 时间范围
- 状态
- 类型
- 分组
- Provider
- 模型
- 能力
- 标签
- 是否启用

筛选区默认一行展示常用筛选，更多筛选进入展开面板。

### 7.3 对象详情 Inspector

对复杂对象使用右侧 Inspector：

- 基础信息
- 状态
- 关联对象
- 最近操作
- 审计记录
- 权限影响
- 用量摘要
- 快捷操作

适用对象：

- 用户
- 用户组
- Provider
- 模型
- RH 条目
- 公共资源
- 公告
- 任务
- 环境同步差异项

### 7.4 配置保存

所有配置页统一保存状态：

- 未修改
- 有未保存修改
- 保存中
- 已保存
- 保存失败
- 版本冲突
- 已保存但未确认实际生效
- 已保存且实际生效

对于会影响运行态的参数，保存后必须展示：

- 配置值
- 实际生效值
- 最近上报时间
- 生效差异提示

### 7.5 批量操作

所有批量操作必须分三步：

1. 选择对象。
2. 预览影响。
3. 二次确认并执行。

适用场景：

- 批量禁用账号
- 批量调整用户组
- 批量开放 / 禁用公共资源
- 批量启停模型
- 批量启停 RH 条目
- 批量归档公告
- 批量同步环境对象

### 7.6 空状态、加载、错误

统一规则：

- 空状态说明“当前没有数据”和“下一步可以做什么”。
- 加载态不能造成布局跳动。
- 局部表单错误只显示在局部，不升级为全局错误。
- 全局错误只用于 API 连接失败、权限异常、系统级不可恢复错误。
- 长文本错误必须可展开查看，不允许撑坏布局。

## 8. 页面设计

## 8.1 运营总览

### 8.1.1 作用

运营总览是后台第一屏，用于回答四个问题：

- 平台现在是否健康？
- 哪些能力正在被使用？
- 哪些地方有风险？
- 管理员下一步最应该处理什么？

### 8.1.2 页面结构

1. 环境与健康条
   - 当前环境：gray / production
   - 当前版本
   - API 连接状态
   - 数据库状态
   - Redis 状态
   - Worker 状态
   - 告警数量

2. 核心 KPI 条带
   - 今日成功任务
   - 当前排队任务
   - 当前运行任务
   - 24h 失败任务
   - 启用模型数
   - 启用 RH 条目数
   - 公共资源数
   - 活跃用户数

3. 能力用量可视化
   - 图像 / 视频 / LLM / 音频 / RH App / RH Workflow 占比
   - 今日 vs 7 日均值
   - Top 模型
   - Top RH 条目

4. 队列运行态
   - 按能力显示排队深度
   - 实际生效并发
   - Worker 槽位
   - RH 平台窗口占用

5. 风险雷达
   - 失败趋势
   - requestId 覆盖率
   - revision 冲突
   - Provider 探测失败
   - 环境差异

6. 最近变更
   - 最近 Provider / 模型变更
   - 最近 RH 条目变更
   - 最近权限策略变更
   - 最近公共资源变更
   - 最近公告发布

### 8.1.3 交互

- 任意 KPI 点击进入对应模块并带筛选。
- 风险项点击进入排障详情。
- 最近变更点击进入对象 Inspector。
- 支持时间范围切换：今日、7 天、30 天、自定义。

## 8.2 能力配置

### 8.2.1 工作域主页

能力配置主页展示：

- Provider 总数 / 启用数
- 模型总数 / 启用数
- RH AI 应用数
- RH 工作流数
- 节点能力数
- 最近失败的模型测试
- 最近变更的能力
- 被权限限制最多的能力

### 8.2.2 Provider 管理

保留现有能力：

- 新增 Provider
- 编辑名称、协议、Base URL、备注
- Key 写入和掩码展示
- 验证地址
- 拉取模型
- 删除 Provider
- AI 协助配置

目标结构：

- 左侧 Provider 列表
- 中间 Provider 基础参数
- 右侧 Provider Inspector
- 下方关联模型、RH 条目和审计

交互重点：

- Provider 保存不等于模型可用，必须显示探测状态和最近探测时间。
- 删除 Provider 前预览受影响模型和画布节点。
- RunningHub Provider 在摘要中显示 RH Key 池、工作流、AI 应用。

### 8.2.3 模型目录

模型从 Provider 页面里下沉出来，成为独立二级页。

功能：

- 按 Provider、能力、启用状态筛选模型。
- 查看模型显示名、模型 ID、能力、能力标签、执行模式、输入 profile、参数 schema。
- 测试模型。
- 自动应用测试推断的能力标签。
- 启用 / 停用。
- 批量导入拉取结果。

模型详情 Inspector：

- 基础参数
- 输入能力
- 参数 schema
- 高级配置
- 测试记录
- 近 7 / 30 天成功用量
- 失败任务下钻
- 哪些用户组可见 / 被限制

### 8.2.4 RH AI 应用与 RH 工作流

保留现有 RH 工作台能力，但拆成两个清晰入口：

- RH AI 应用
- RH 工作流

共同结构：

- 左侧目录列表
- 顶部搜索、状态、Provider、能力筛选
- 中间结构化编辑器
- 右侧测试和影响 Inspector
- 下方 AI 分析草案区

每个 RH 条目展示：

- 标题
- catalogId
- runTargetId
- Provider
- 启用状态
- 能力类型
- 输入槽数量
- 参数 schema 数量
- 输出定义
- 是否允许无入参
- 用量和权限摘要

关键交互：

- AI 分析草案必须以卡片展示，可单卡应用、整套应用、另存为新条目。
- 保存前预览本次变更影响：节点参数、权限目录、用量统计名称。
- 测试结果保留请求预览和响应预览。
- 对混合态配置给明确警告。

### 8.2.5 RH Key 池

RH Key 池从 RH 工作台中抽成能力配置的子页或嵌入页。

功能：

- 查看每个 Key 的备注、掩码、启用状态、默认状态、最大并发、当前占用。
- 新增、保存、删除、设为默认。
- 自动汇总 RH 平台总并发。
- 显示当前 RH 队列窗口状态。

交互：

- 修改 Key 池后需要展示“配置总并发”和“实际窗口占用”。
- 删除 Key 前预览当前是否有任务正在占用。

### 8.2.6 节点能力目录

节点能力目录用于承接后续权限和节点治理。

功能：

## 9. 权限与数据模型原则

### 9.1 分组优先

权限治理以用户组为主：

- 用户属于一个组。
- 组拥有 deny 策略。
- 管理员角色拥有后台管理能力。
- 普通用户界面根据有效权限隐藏不可用内容。

### 9.2 deny 策略继续成立

当前 `GroupPermissionDeny` 继续作为第一阶段策略：

- `sharedResourceCategoryIds`
- `sharedResourceItemIds`
- `runningHubAppCatalogIds`
- `runningHubWorkflowCatalogIds`
- `nodeTypes`

后续可扩展：

- `providerIds`
- `modelRecordIds`
- `operationIds`
- `adminModuleIds`

### 9.3 隐藏优先

对于普通用户：

- 无权限公共资源：资源库不显示。
- 无权限 RH 应用 / 工作流：目录不显示。
- 无权限节点能力：节点面板不显示。
- 旧画布残留或绕过请求：后端提交口兜底拦截。

后台中可以显示“该组禁用 / 允许”，但前台不展示拒绝态。

### 9.4 审计必须覆盖关键操作

以下操作必须进入审计：

- 用户创建、禁用、分组调整、密码重置。
- 用户组创建、修改、删除。
- 权限策略修改。
- Provider / 模型创建、修改、删除、启停。
- RH 条目创建、修改、删除、启停。
- RH Key 池修改。
- 公共资源上传、修改、删除。
- 公告发布、归档、删除。
- 任务取消、重试。
- 系统参数修改。
- 环境同步执行。

## 11. 响应式与防溢出规范

### 11.1 文本

- 中文标题允许换行。
- 英文 ID、URL、邮箱、requestId 必须支持省略和复制。
- 表格长文本默认省略，详情中完整展示。
- 按钮文字不允许被压缩到不可读。

### 11.2 卡片

- 卡片宽度有最小值和最大值。
- 卡片操作按钮允许换行。
- 卡片内预览区使用固定比例或固定高度边界。
- 卡片不能因为动态内容导致整体跳动。

### 11.3 表格

- 表格支持横向滚动，但滚动区域必须是完整表格区域。
- 关键列固定或优先展示。
- 长字段使用复制按钮或 Inspector 完整展示。

### 11.4 滚动

禁止局部小滚动陷阱：

- 左侧列表滚动必须覆盖完整列表面板。
- 主内容滚动必须在工作区层级。
- Inspector 独立滚动时必须有明确边界。
- 页面不能同时出现无意义的双滚动条。

### 11.5 状态颜色

- 选中态、成功态、警告态、危险态必须区分。
- 主强调色只用于当前选中和主按钮。
- 成功色只用于保存成功、健康、允许。
- 警告色只用于待处理、冲突、限制。
- 危险色只用于删除、失败、不可逆风险。

## 14. 验收标准

### 14.1 功能覆盖

- 当前 11 个后台入口的能力全部能在新 IA 中找到对应位置。

### 14.4 布局质量

- 卡片按钮自动换行后仍可读。
- 表格长字段不撑爆页面。
- 不出现无意义的双滚动条。
- 不出现只能在很小区域滚动的局部陷阱。

### 14.5 运维与审计

- 参数保存能区分配置值和实际生效值。
- 关键后台变更进入审计。
- 环境同步保留预览、确认、结果和审计。
- 系统健康能表达数据库、Redis、Worker、队列和告警状态。

---

## 15. 设计决议

本轮整体后台改造采用：

- 五工作域信息架构。
- 可视化先行、表格治理承接。
- 组权限为主、无权限前台隐藏。
- 配置保存与实际生效分离。
- 统一 Inspector、筛选、批量、保存、审计模式。

不采用：

- 继续平铺增加菜单。
- 只在现有页面上做局部 CSS 美化。
- 为每个新增功能单独创造一套页面交互。
- 前台对无权限内容显示拒绝状态。

后续进入实施前，应基于本设计拆分正式实施计划，并按阶段控制变更范围和灰度验收。
