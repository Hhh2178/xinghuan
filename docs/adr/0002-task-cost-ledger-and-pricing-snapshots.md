# ADR 0002：任务费用台账与价格版本快照

> **Status:** Accepted  
> **Date:** 2026-07-21  
> **Owners:** Admin / API / Worker / Storage  
> **Decision Scope:** 模型价格、任务费用快照与费用统计  
> **Supersedes:** None

## Context

平台需要按服务商、模型、用户组和账号统计费用。模型价格会变化，用户也会换组；若用当前价格和当前目录实时重算历史任务，历史账务会漂移。任务由 API、Worker 和同步代理等多个入口写入，逐入口结算容易漏账或重复入账。

## Decision

1. 价格使用追加式版本表；改价创建新版本并关闭旧生效区间。
2. 任务创建时生成费用项并锁定价格、owner/group/provider/model 快照。
3. 任务终态以 PostgreSQL 触发器原子、幂等结算；TypeScript 提供同构业务规则、API 和测试。
4. 成功任务计费；用户取消仅在上游确认取消成功时免计费，其余取消计费；失败不计费。
5. 按秒计费使用权威时长优先级并向上取整为整数秒。
6. 既有历史任务不回填；无有效价格的新任务记录为未定价。
7. 金额使用十进制定点值；多币种分别汇总，不做隐式换算。

## Alternatives

- 查询时实时计算：拒绝，因为价格和用户组变化会改写历史。
- 只在 Worker 结算：拒绝，因为同步成功任务和 API 取消路径可能绕过 Worker。
- 把费用写进 `xh_tasks.result`：拒绝，因为无法形成可扩展、可审计、幂等的费用明细。

## Consequences

- 数据模型增加价格版本和费用台账两张表，以及任务生命周期触发器。
- 归属和金额历史稳定，可在未来追加 adjustment/internal charge，而不改写 provider cost。
- 回滚应用时保留账务数据，避免破坏性迁移。

## Verification

- 自动化覆盖成功、失败、三类取消、按次、按秒、改价、未定价和幂等。
- Gray 验证迁移、任务结算、聚合 API 和 Admin 柱状图。

## Migration And Rollback

- Migration 025 只为迁移后的新任务创建费用项，不回填既有任务。
- 应用可回滚到上一 Gray 制品；价格与费用表保留，禁止破坏性删表。
- 若触发器本身需要紧急停用，通过新的受控迁移处理，不在运行服务器手工改表。
