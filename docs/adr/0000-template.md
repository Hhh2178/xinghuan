# ADR NNNN: 标题

> **Status:** Proposed  
> **Date:** YYYY-MM-DD  
> **Owners:** 责任域或角色  
> **Decision Scope:** 涉及的系统边界  
> **Supersedes:** None

## Context

描述问题、约束、已有事实和为什么现在需要决定。不要把提案写成已经上线的事实。

## Decision

描述选择及其边界。若为 Proposed，明确哪些内容仍待批准。

## Alternatives

- 方案 A：优点、缺点和未选择原因。
- 方案 B：优点、缺点和未选择原因。

## Consequences

### Positive

- 带来的收益。

### Negative

- 接受的成本和限制。

## Verification

- 如何通过契约、测试、观测或运行态证据确认决定被正确实现。

## Migration And Rollback

- 迁移阶段、兼容边界、回滚条件和数据保护措施。
