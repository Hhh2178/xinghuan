# Canvas 项目与素材流

## 典型链路

1. 用户在画布中编排节点
2. 前端提交任务到 API
3. Worker / API 输出保存路径在服务端登记 Generation Artifact
4. 前端再通过统一素材访问层回读

## 当前重点边界

- 项目主存储走云端，不以本地文件夹为主
- 生成库内容访问已统一走素材访问层
- 资源库、生成库与节点结果要共享访问语义
- 账号换组不得改变画布、个人资源和任务 ownership。
- 后台发布的视频模型按 `inputCapabilities` 与参数 Schema 决定图片、视频、音频素材入口；参考视频必须经过画布节点、API 校验、任务队列与 Worker 全链路传递，不能只在本地 Provider 分支生效。

## 文件快照恢复

- PostgreSQL 是当前画布列表权威源，本地 JSON 只作为迁移兼容快照。
- 即使 `.postgres-migration-complete` 已存在，只要 DB 与文件集合不完整一致，仍需识别孤立快照。
- 恢复只插入当前 owner 缺失的 ID，批量操作使用事务；跨 owner ID 冲突整体回滚并报告。
- 原始 JSON 保留，重复扫描必须幂等。

## 当前资源域划分

- `我的资源库`
  - 用户私有资源，支持常规分类、收藏、插入画布、发送素材、工作流复用。
- `公共资源库`
  - 面向全体用户可见与可用。
  - 当前首批能力支持前台双库浏览、管理员轻编辑、管理员上传媒体类公共资源、普通用户另存为我的资源。
  - 共享资源条目保留独立索引，不直接并回个人资源表。
- `生成库`
  - 面向任务产物浏览、预览、下载与回流使用。
  - 卡片与完整预览正在向资源库交互壳统一，减少两套预览和动作语义分叉。
  - Canvas 不扫描节点结果登记产物；生成库是服务端 owner-scoped 查询视图。
  - “保存到资源库”调用显式 Promotion，并显示已保存状态。

## 工作流模板导出语义

- 工作流保存到资源库、导出 JSON、以及后续作为资源复用时，统一走“干净模板”语义。
- 导出前会清理节点运行态残留，包括历史消息、旧任务结果、轮询态、错误态和临时输出。
- 与资源库关联的索引字段需要保留，避免共享资源在工作流模板中被错误拍平成一次性 URL。

## 画布媒体与运行任务恢复

- 普通画布保存、自动保存、刷新恢复和前端版本切换必须保留节点媒体、尺寸及生成任务运行态；只有工作流 manifest 构建可以在深拷贝上清理这些字段。
- 同一浏览器的多标签画布保存通过 Web Locks 串行化；成功保存后使用 BroadcastChannel 广播新 revision。无本地改动的标签页自动重载服务端新版本，有未保存改动的标签页在发请求前暂停自动保存并提示冲突。
- 跨设备与不支持浏览器协调 API 的客户端仍由服务端 `expectedRevision` 乐观锁保护；前端协调只能减少可预防的 409，不能绕过或替代服务端冲突检查。
- Upload 与 Output 的单图/单视频使用素材固有比例计算初始尺寸，手动四角拉伸继续锁定该比例；多素材使用响应式网格与 `object-fit: contain` 完整展示。
- Upload 单媒体节点计算预览外 chrome 时统一使用未受 React Flow 缩放影响的 layout CSS pixels（`offset*` / `scrollHeight`）；禁止把 viewport rect 与 layout metrics 混算后写入 `data.size`。媒体 metadata 在刷新后会按当前素材比例重新校正旧尺寸。
- 异步生成节点在每个批次拿到远程任务号后立即持久化 `taskRuns[]`。每项至少包含 `batchIndex`、`taskId`、`resumeKind`、`status`，旧协议所需查询参数放入 `resumeParams`。
- 节点刷新挂载时只恢复查询原任务，不调用提交接口；批量任务逐项查询，完成结果与已保存 URL 去重合并，失败或取消按批次记录终态。
- 当前恢复路由覆盖后台图像、视频、音频任务，MJ、图像/视频 FAL、旧图像/视频轮询及 Seedance。已禁用的旧 Suno 链路不在运行态启动恢复。

## 公共资源库当前链路

1. 前台资源库抽屉切换到 `公共资源库`
2. 管理员可新增分类、上传首批媒体类资源、编辑条目基础信息
3. 普通用户只能浏览、插入、发送素材、另存为个人资源
4. 后端通过独立 `shared-resource` 路由与独立存储文件管理共享资源
5. 共享资源另存为个人资源时，会生成新的个人资源记录，但保留源资源内容与引用语义

## 共享工作流链路

1. 管理员在后台 ComfyUI 实例页维护 `实例专属工作流`
2. 草稿工作流可以编辑暴露参数口、默认值、输出口
3. 需要对全体画布开放时，再点击 `推送到共享区`
4. 共享工作流进入独立共享目录，被 `ComfyUI应用` 节点消费
5. 画布用户只选择共享工作流，不直接改写实例草稿

## 公共资源库里的工作流上传

- 公共资源库的工作流上传现在兼容两种 JSON：
  - 标准 `t8-workflow-fragment`
  - 普通画布导出对象 `nodes / edges`
- 上传后统一会被归一化成工作流资源 manifest，再进入共享资源库索引
- 与 ComfyUI 共享工作流不同：
  - 资源库工作流偏模板复用
  - `共享工作流` 偏后台治理后的可执行应用目录
