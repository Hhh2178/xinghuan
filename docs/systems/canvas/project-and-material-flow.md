# Canvas 项目与素材流

## 典型链路

1. 用户在画布中编排节点
2. 前端提交任务到 API
3. 任务结果回写生成库与输出素材
4. 前端再通过统一素材访问层回读

## 当前重点边界

- 项目主存储走云端，不以本地文件夹为主
- 生成库内容访问已统一走素材访问层
- 资源库、生成库与节点结果要共享访问语义

## 当前资源域划分

- `我的资源库`
  - 用户私有资源，支持常规分类、收藏、插入画布、发送素材、工作流复用。
- `公共资源库`
  - 面向全体用户可见与可用。
  - 当前首批能力支持前台双库浏览、管理员轻编辑、管理员上传媒体类公共资源、普通用户另存为我的资源。
  - 共享资源条目保留独立索引，不直接并回个人资源表。
- `生成库`
  - 面向任务产物浏览、预览、下载与回流使用。
  - 卡片与完整预览正在向资源库交互壳统一，减少两套预览和动作语义分叉。

## 工作流模板导出语义

- 工作流保存到资源库、导出 JSON、以及后续作为资源复用时，统一走“干净模板”语义。
- 导出前会清理节点运行态残留，包括历史消息、旧任务结果、轮询态、错误态和临时输出。
- 与资源库关联的索引字段需要保留，避免共享资源在工作流模板中被错误拍平成一次性 URL。

## 公共资源库当前链路

1. 前台资源库抽屉切换到 `公共资源库`
2. 管理员可新增分类、上传首批媒体类资源、编辑条目基础信息
3. 普通用户只能浏览、插入、发送素材、另存为个人资源
4. 后端通过独立 `shared-resource` 路由与独立存储文件管理共享资源
5. 共享资源另存为个人资源时，会生成新的个人资源记录，但保留源资源内容与引用语义
