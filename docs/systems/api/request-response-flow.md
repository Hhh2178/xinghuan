# API 请求与响应链路

## RunningHub 分析链路

1. 后台提交 `requestExample / responseExample`
2. API 解析样例并推断字段、输出和执行规则草案
3. 后台将草案应用为条目结构

## 任务提交链路

1. 前端或后台发起请求
2. API 做鉴权、参数校验和条目解析
3. API 写入本地任务
4. Worker 消费并调用外部平台
5. 查询结果后回写任务状态

任务身份规则：创建时写入 `owner_id`；Worker 只更新状态、日志和结果，不更新 owner；后台列表使用统一 owner 解析表达式兼容历史空值，但不把回退值写回数据库。

## 用户目录写入链路

1. 后台校验管理员身份和目标用户组。
2. 用户、用户组和策略通过各自的定点 repository 写入。
3. 用户组与默认策略需要原子创建时，只在一个事务中插入这两条目标记录。
4. 禁止通过删除重建 `xh_users` 同步目录快照，避免触发画布、项目、素材和任务外键动作。

## 系统并发链路

1. 后台保存并发配置
2. API 返回最新系统设置
3. Worker 周期刷新并发槽位
4. `/api/admin/system` 聚合“配置值”和“实际生效值”
