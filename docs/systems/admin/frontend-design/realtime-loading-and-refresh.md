# 懒加载、热加载与实时刷新规则

本文件记录 Admin 后台前端在页面加载、模块懒加载、数据自动刷新、任务状态热刷新、前端版本更新恢复方面的设计规则。

## 1. 总原则

Admin 后台要支持：

- 页面懒加载。
- 数据按需加载。
- 任务和系统状态自动刷新。
- 长任务日志持续更新。
- 前端版本更新后的 chunk 失效恢复。
- 未保存表单保护。

目标：

- 首屏轻。
- 重页面按需加载。
- 实时状态及时更新。
- 不打断管理员正在编辑或查看的内容。

## 2. 页面懒加载

### 必须懒加载的页面

- Provider 管理。
- 模型目录。
- RH AI 应用。
- RH 工作流。
- RH Key 池。
- 公共资源管理。
- 生成库后台治理。
- 用量分析。
- 审计日志。
- 任务列表。
- 系统健康。
- 环境同步。

### 首屏应加载

- 后台 Shell。
- 当前管理员。
- 当前环境和版本。
- 全局告警摘要。
- 运营总览首屏 KPI。

### 加载体验

- 页面级 skeleton。
- 局部面板 skeleton。
- 表格加载态。
- 卡片网格加载态。
- Inspector 加载态。

禁止：

- 首次进入后台时一次性加载所有页面数据。
- 懒加载失败导致白屏。
- 页面切换时布局大幅跳动。

## 3. 数据刷新策略

### 自动刷新页面

运营总览：

- KPI、队列、系统健康、告警建议 5-10 秒刷新。
- 趋势图可 30-60 秒刷新或手动刷新。

任务队列：

- 队列深度、running、queued、Worker、槽位建议 3-5 秒刷新。

任务列表：

- queued / running 任务建议 3-5 秒刷新。
- succeeded / failed / cancelled 不需要高频刷新。

任务详情：

- 当前选中任务为 running / queued 时，状态和日志建议 2-3 秒刷新。

系统健康：

- 数据库、Redis、Worker、队列、告警建议 5-10 秒刷新。

告警中心：

- 活动告警建议 10 秒刷新。

### 手动刷新页面

以下页面默认不高频自动刷新：

- Provider 管理。
- 模型目录。
- RH 条目编辑。
- 公共资源编辑。
- 权限策略。
- 公告编辑。
- 环境同步差异预览。
- 运行参数。

原因：

- 这些页面涉及编辑状态。
- 自动刷新容易覆盖草稿或造成误判。

## 4. 任务列表热刷新

### 刷新对象

任务列表刷新时只更新：

- 新增 queued / running。
- running 状态变化。
- queued 状态变化。
- 当前筛选范围内任务的 displayStatus、displayMessage、runtimeStage、providerState、updatedAt。

### 不应打断

自动刷新不能：

- 清空筛选条件。
- 重置分页。
- 重置滚动位置。
- 改变当前选中任务。
- 覆盖用户正在展开查看的日志。

### 当前选中任务

任务详情 Inspector 支持：

- 独立刷新。
- 自动跟随日志到底部开关。
- 暂停刷新开关。
- 最新状态标记。

### 操作按钮刷新

根据任务状态显示：

- queued / running：取消。
- failed / cancelled：重试。
- succeeded：无操作或查看详情。

状态变化后按钮要自动更新。

## 5. 系统健康热刷新

系统健康刷新内容：

- API 状态。
- 数据库状态。
- Redis 状态。
- Redis 队列深度。
- Worker 数。
- 槽位数。
- RH 平台窗口。
- 失败趋势。
- requestId 覆盖率。
- revision 冲突。
- 活动告警。

刷新时要求：

- 图表平滑更新。
- 不重置用户展开的分区。
- 不关闭 Inspector。
- 异常状态必须在下一轮刷新中保持可见。

## 6. 表单和配置保护

以下页面存在草稿状态，自动刷新必须谨慎：

- Provider 管理。
- 模型详情。
- RH AI 应用。
- RH 工作流。
- RH Key 池。
- 公共资源编辑。
- 权限策略。
- 公告编辑。
- AI 助手配置。
- AI 托管治理配置。
- 运行参数。

规则：

- 有未保存修改时，不自动覆盖表单。
- 版本化治理工作区有未保存修改时，不卸载当前编辑器；跨工作区切换必须先明确留在当前页或放弃修改，手动刷新保持禁用。
- 后端数据发生变化时显示“远端已更新”提示。
- 用户可选择刷新为最新或继续编辑。
- 保存时携带 revision。
- 冲突时展示冲突提示，并给出刷新最新配置的入口。

## 7. 前端热加载与版本更新恢复

后台灰度或生产发布后，旧标签页可能加载到失效 chunk。必须支持恢复。

### 需要处理的情况

- dynamic import 失败。
- chunk 404。
- 旧版本页面切换到新懒加载模块失败。
- service worker 或缓存导致静态资源不一致。

### 体验规则

- 不白屏。
- 显示“后台已更新，需要刷新页面”提示。
- 提供“立即刷新”按钮。
- 尽量保留当前路径、筛选条件、选中对象。
- 如果有未保存修改，不静默刷新。

### 可恢复信息

应尽量保存：

- 当前工作域。
- 当前页面。
- 筛选条件。
- 搜索词。
- 当前选中对象 ID。
- 是否打开 Inspector。

不应保存：

- API Key 明文。
- 密码。
- 未脱敏敏感字段。

## 8. 刷新频率建议

| 页面 | 默认刷新 | 备注 |
| --- | --- | --- |
| 运营总览 KPI | 5-10 秒 | 可暂停 |
| 任务队列 | 3-5 秒 | 高频运行态 |
| 任务列表 | 3-5 秒 | 只对活跃任务高频 |
| 任务详情日志 | 2-3 秒 | 可自动跟随 |
| 系统健康 | 5-10 秒 | 保持分区展开状态 |
| 告警中心 | 10 秒 | 可手动刷新 |
| 用量分析 | 手动 / 30-60 秒 | 避免频繁重算 |
| 环境同步 | 手动 | 预览不自动执行 |
| 配置表单 | 手动 | 有草稿保护 |

## 9. 用户控制

自动刷新页面需要提供：

- 自动刷新开关。
- 最近刷新时间。
- 手动刷新按钮。
- 刷新中状态。
- 刷新失败提示。

任务日志需要提供：

- 自动跟随到底部。
- 暂停跟随。
- 清空本地显示，不清空真实日志。

## 10. 验收标准

- 切换后台页面时重页面按需加载。
- 懒加载失败时不白屏。
- 任务 running 状态能自动变更为 succeeded / failed。
- 任务详情日志能持续更新。
- 自动刷新不重置筛选、分页、滚动和选中对象。
- 有未保存修改时，远端刷新不覆盖草稿。
- 发布新版本后旧标签页能提示刷新恢复。
