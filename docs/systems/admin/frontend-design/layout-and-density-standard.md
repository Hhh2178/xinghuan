# Admin Layout And Density Standard

## Shell

- Left navigation owns primary module switching.
- Top status area owns environment, version, session, and global state.
- Main content owns page-specific tables, forms, cards, and workbenches.
- Right-side inspector or drawer owns details and secondary actions.

## Density

- Dense data views may use compact tables.
- Form-heavy pages need clear group spacing and section titles.
- KPI cards should not compete with primary work actions.
- Operations pages should prefer fewer strong visual surfaces over many equal-weight panels.

## Page Rhythm

- Page title, description, primary action, and status summary must align in a predictable header zone.
- Filters and batch actions belong above tables.
- Long-running task pages should keep queue status visible while details change.

## Responsive Behavior

- Desktop is the primary admin target.
- Narrow screens should preserve reading, inspection, and emergency operations, even if dense management workflows are reduced.
