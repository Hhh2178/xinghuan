# Admin 前端设计增改规范

本文件用于指导后续 Admin 后台功能增减、页面修改和设计调整，确保长期保持统一风格和交互逻辑。

## 1. 新增页面前先判断工作域

新增功能不能直接新增一级菜单。先判断归属：

- 运营数据、趋势、风险：进入运营总览。
- Provider、模型、RH、节点、AI 助手：进入能力配置。
- 公共资源、生成库、公告、标签：进入资源与内容。
- 账号、用户组、权限、会话、用量、审计：进入组织与治理。
- 系统健康、队列、任务、环境同步、发布：进入系统与发布。

只有当功能不属于任何工作域时，才讨论新增一级工作域。

## 2. 新增页面必须记录

新增页面时，至少记录：

- 页面名称。
- 所属工作域。
- 页面作用。
- 用户任务。
- 主要区块。
- 主要字段。
- 操作按钮。
- 状态。
- 是否需要 Inspector。
- 是否需要自动刷新。
- 是否影响权限目录。
- 是否需要审计。

记录位置：

- `page-map-and-functions.md`
- 如涉及刷新：`realtime-loading-and-refresh.md`
- 如涉及视觉组件：`visual-style-and-stitch-baseline.md`

## 3. 页面结构标准

常规页面优先采用：

- 页面标题区。
- 摘要 / KPI 区。
- 筛选和操作栏。
- 主列表 / 表格 / 卡片区。
- Inspector。
- 保存条或确认弹窗。

配置类页面必须包含：

- 当前值。
- 草稿值。
- 未保存状态。
- 保存中。
- 保存成功。
- 保存失败。
- revision 冲突。
- 实际生效值，若适用。

## 4. Inspector 使用规则

适合使用 Inspector 的对象：

- 用户。
- 用户组。
- Provider。
- 模型。
- RH 条目。
- 公共资源。
- 生成结果。
- 任务。
- 审计记录。
- 环境同步差异项。

Inspector 需要展示：

- 基础信息。
- 状态。
- 关联对象。
- 最近审计。
- 用量或运行摘要。
- 权限摘要，若适用。
- 快捷操作。

## 5. 自动刷新判断

需要自动刷新：

- 任务状态。
- 任务日志。
- 队列深度。
- Worker / 槽位。
- 系统健康。
- 活动告警。
- 运营总览关键 KPI。

不默认自动刷新：

- 配置表单。
- 权限策略编辑。
- 公共资源编辑。
- 公告编辑。
- 环境同步执行。

如果自动刷新可能覆盖用户编辑内容，必须改为手动刷新或加草稿保护。

## 6. 权限相关改动

新增以下对象时，必须考虑权限：

- 公共资源类型。
- RH 条目类型。
- 节点能力。
- 模型或 Provider 级能力。
- 内容资产。

权限页面需要更新：

- 权限对象列表。
- 影响预览。
- 批量允许 / 禁用。
- 历史缺失 ID 展示。

前台规则保持：

- 无权限内容直接隐藏。

## 7. 审计相关改动

以下操作必须有审计：

- 新增。
- 修改。
- 删除。
- 启用。
- 停用。
- 发布。
- 归档。
- 同步。
- 取消任务。
- 重试任务。
- 修改权限。
- 修改系统参数。

新增操作时，应在页面设计中提供审计入口或最近变更摘要。

## 8. 资源预览规则

所有图片、视频、音频相关页面必须遵守：

- 预览使用黑底容器。
- 内容完整显示。
- 不裁切主体。
- 不强行铺满容器。
- 支持完整预览弹层。

适用：

- 公共资源。
- 生成库。
- RH 条目缩略图。
- 权限策略中的资源预览。

## 9. 防溢出规则

设计和实现都必须满足：

- 中文标题可换行。
- 英文 ID、URL、邮箱、requestId 可省略和复制。
- 表格长字段不撑爆页面。
- 卡片按钮可以换行。
- 分类、标签、状态 pill 不撑爆父容器。
- 局部滚动必须是完整面板，不是窄小区域。

## 10. 高风险操作规则

以下操作必须有确认弹窗：

- 删除 Provider。
- 删除模型。
- 删除 RH 条目。
- 删除 RH Key。
- 删除公共资源。
- 删除用户组。
- 禁用账号。
- 发布强提醒公告。
- 环境同步。
- 修改系统关键参数。
- 取消任务，若任务正在运行。

确认弹窗必须展示：

- 操作对象。
- 影响范围。
- 风险说明。
- 取消按钮。
- 确认按钮。

## 11. 设计评审清单

每次后台 UI 设计变更评审前，检查：

- 是否符合五大工作域。
- 是否保留 stitch 基线风格。
- 是否出现品牌命名混乱。
- 是否有文字溢出风险。
- 是否有按钮挤压风险。
- 是否有双滚动条或小滚动陷阱。
- 是否明确空态、加载态、错误态。
- 是否需要自动刷新。
- 是否需要审计。
- 是否影响权限隐藏规则。
- 是否保留对象下钻路径。
