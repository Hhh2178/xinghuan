# 视觉风格与 stitch 基线

## 1. 结论

`stitch` 设计方案可以作为 Admin 后台新版 UI 的视觉基底，但不能作为完整后台设计直接落地。

可以保留：

- 深色科技控制台风格。
- 青色主强调色。
- 小圆角、细边框、数据密集布局。
- 左侧导航 + 顶部状态栏。
- KPI 卡片。
- 右侧 Inspector 详情面板。
- 资源预览黑底 `contain` 逻辑。
- 系统健康拓扑图。
- 任务列表 + 右侧任务详情日志。
- 环境同步左右对比感。

必须调整：

- 信息架构以当前十个职责域及稳定 URL 为准。
- 品牌统一为“星幻无限画布”。
- 补齐完整后台页面。
- 公共资源改成真正的卡片网格。
- 权限治理改成按组的权限矩阵。
- 环境同步补齐差异表、冲突决策、勾选同步和结果反馈。
- AI 助手配置拆成创作侧、后台侧、外部接入和上下文权限。
- 全局常驻的“部署新节点”按钮移除，不作为普通全局主操作。

## 2. 视觉关键词

- 专业生产工具。
- 运营驾驶舱。
- 科技黑。
- 电磁青强调。
- 高信息密度。
- 精密感。
- 数据可视化。
- 参数控制台。

## 3. 色彩方向

基础方向：

- 页面背景使用深色。
- 容器使用略亮的深灰 / 深锌色。
- 主强调使用青色。
- 成功、警告、危险必须使用语义色，不能和选中态混淆。

状态色职责：

- 主强调色：当前选中、主按钮、关键数据高亮。
- 成功色：健康、连接正常、保存成功、任务成功。
- 警告色：排队、配置缺失、性能下降、冲突待处理。
- 危险色：失败、断开、删除、禁用、不可逆操作。

禁止：

- 选中态、允许态、成功态全都使用同一种高亮色。
- 用大面积发光装饰抢占数据主视觉。
- 用低对比文字表达关键状态。

## 4. 字体和信息层级

建议：

- 中文和普通 UI：Source Sans 3 / Source Han Sans SC / Microsoft YaHei。
- 数字、ID、日志、代码：JetBrains Mono 或等宽字体。

层级：

- 页面标题：用于页面身份，不要过大。
- 区块标题：用于面板分区。
- 数据数字：允许更强视觉重量。
- 描述文本：降低权重，但必须可读。
- ID / requestId / catalogId / runTargetId：使用等宽字体，支持复制。

## 5. 组件基线

### 左侧导航

- 一级工作域以 `ui-and-information-architecture.md` 的十域路由为准，不在视觉文档复制另一份导航清单。
- 支持折叠。
- 选中态清晰，但不应比主内容更抢眼。
- 不放全局高风险按钮。

### 顶部状态栏

展示：

- 当前环境。
- 当前版本。
- API 状态。
- 全局搜索。
- 告警入口。
- AI 助手入口。
- 当前管理员。

要求：

- 窄宽度下自动收纳次要信息。
- 环境和版本始终可见。

### KPI 卡

展示：

- 标题。
- 数值。
- 单位或说明。
- 趋势。
- 状态。
- 下钻入口。

要求：

- 指标必须能点击进入对应列表或详情。
- 不做纯装饰数字。

### Inspector

用途：

- 当前对象详情。
- 关联对象。
- 最近审计。
- 用量摘要。
- 权限摘要。
- 快捷操作。

要求：

- 右侧固定或抽屉。
- 内容过长时 Inspector 内部滚动。
- 不挤压主工作区到不可用。

### 表格

要求：

- 适合大量数据。
- 长字段省略，支持复制或完整查看。
- 行点击进入 Inspector。
- 操作列固定或明确。

### 组织治理工作区

要求：

- 组织与治理页顶部先展示治理概览条，再进入账号 / 用户组 / 权限 / 会话的分区工作台。
- 组织与治理工作域进入后先给域级 overview 首页，再进入账号 / 用户组 / 权限 / 会话 / 审计的分区工作台。
- 用户组工作区采用左侧创建轨道、右侧卡片工作台，不允许退回窄侧栏式编辑。
- 账号管理工作区采用左侧创建轨道、右侧治理摘要 + 巡检卡 + 账号表治理台，不回退为裸表格页。
- 会话管理工作区采用摘要条 + 提示卡 + 会话表治理台，确保“先判断，再执行下线”。
- 用量分析工作区采用“治理摘要条 + KPI + overview 面板 + 图表 / 矩阵”结构，不允许只剩散落的统计卡和表格。
- 用户组卡片内部必须分成标题区、限制摘要区、编辑区和操作区。
- 权限策略页左侧 rail 负责切组，右侧编辑器负责主视觉和主要交互。
- 权限页需要有影响面板，直接告诉管理员当前组限制了多少对象。
- 权限策略页右侧编辑器必须先给出“当前域说明 + 影响范围 + 批量操作提示”，再进入具体对象列表，避免管理员直接面对无上下文的开关墙。
- RH / 节点能力权限卡片必须使用稳定的上下层结构，下层拆出标题、状态、元信息块和底部权限开关。
- 长 catalogId、runTargetId、nodeType id 不直接裸露在正文流中，统一落入受控 meta block。

落地约定：

- 页面级使用 `users-page--starlight` 标识。
- 组织治理首页使用 `users-governance-overview` 与 `users-governance-quick-grid` 作为固定入口结构。
- 账号治理工作区使用 `users-accounts-workbench--starlight` 标识，会话治理工作区使用 `users-sessions-workbench--starlight` 标识。
- 用量驾驶舱继续使用 `usage-dashboard--starlight` 标识，并补充 `usage-governance-strip` 与 `usage-overview-grid` 作为固定治理部件。
- 用户组工作区使用 `users-group-workbench--starlight` 标识。
- 组织治理概览条使用 `users-governance-summary`，桌面端固定五列，缩窄后自动降列。
- 用户组卡片操作区使用 `users-group-card__action-row`，默认 `flex-wrap: wrap`。
- 权限页使用 `permissions-shell--starlight` 标识，影响面板使用 `permissions-impact-panel`。
- 权限分组名称使用 `permissions-group-card__name`，必须保持白色高对比文本。
- 权限域说明区使用 `permissions-section-overview`，后续扩展新的权限对象时继续复用。

### 资源与内容工作区

要求：

- `公共资源` 与 `生成库` 都应复用统一的资源卡片语言，不允许一个是完整预览卡片、另一个退回旧式杂糅列表。
- `生成库` 卡片继续沿用四列优先网格、黑底完整预览、按钮自动换行。
- 生成结果卡片下半区至少保留：
  - 标题
  - mime / 体积 / 剩余保留时间
  - 任务来源、Provider、模型
  - 转公共资源、删除
- 资源与内容工作域里的媒体预览，一律优先 `contain`，不因“铺满”裁切主画面。

### 资源卡片

要求：

- 桌面一行优先 4 个卡片。
- 上半区为黑底完整预览。
- 图片、视频、音频都不能裁切主体。
- 下半区为标题、分类、标签、备注、文件信息和操作。
- 操作按钮可换行，不溢出。

落地约定：

- 页面级使用 `admin-public-resources-page--starlight` 标识，资源卡片使用 `admin-public-resource-card--starlight` 标识。
- 卡片预览舞台使用 `admin-public-resource-card__preview-stage`，内部媒体统一 `object-fit: contain`。
- 完整预览弹窗使用 `admin-media-preview-modal--starlight`，弹窗媒体同样必须完整展示。
- 操作按钮放入 `admin-public-resource-card__action-row`，所有 action row 默认 `flex-wrap: wrap`。
- 分类名称使用 `admin-public-resources-category-card__name`，文字颜色保持白色，长名称允许安全换行。

## 6. stitch 方案保留与修正清单

保留为设计资产：

- 总览页 KPI 和趋势布局。
- Provider 页左列表 + 中表单 + 右 Inspector。
- 系统健康拓扑图。
- 任务页 KPI + 队列深度 + 任务详情日志。
- 环境同步的左右环境对比。
- 深色细边框控制台语言。

必须重画：

- 左侧导航。
- 公共资源卡片网格。
- 账号 / 用户组 / 权限策略矩阵。
- 模型目录。
- RH AI 应用。
- RH 工作流。
- RH Key 池。
- 用量分析。
- 审计日志。
- 运行参数。
- 发布状态。

## 7. 设计红线

不允许：

- 文字溢出容器。
- 按钮挤压到不可读。
- 表格撑爆页面。
- 卡片因为动态内容高度失控。
- 资源预览裁切主体。
- 分类或分组只能在很小区域滚动。
- 无意义双滚动条。
- 删除、发布、同步等高风险操作没有确认。
- 无权限内容在前台显示拒绝状态。
