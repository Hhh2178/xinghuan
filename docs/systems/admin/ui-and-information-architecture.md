# Admin 信息架构

## 当前信息架构重点

- 后台首页与系统页负责观测与治理
- RunningHub 工作台负责 RH 条目录入、分析、测试和启停
- 配置类页面需要明确区分“保存成功”和“实际生效”
- 审计页当前已升级为“成功用量驾驶舱 + 审计日志表”双层结构
- 用户与权限页下一阶段将以“账号 / 用户组 / 权限 / 会话”分区收口
  - `2026-06-26` 第一版已落地为顶部切换式工作台，不再把分组管理塞进窄侧栏

## RunningHub 工作台当前结构

- 左侧：搜索、分类、状态筛选、条目列表
- 右侧：基础信息、请求/响应示例、输入槽、参数 schema、输出定义、执行规则

## 页面命名原则

- 优先显示用户能理解的业务名称
- 参数有标注时优先显示标注
- 没有标注时回退技术字段名

## 视觉和交互要求

- 不把旧的 `Webapp ID` 等混淆文案暴露给画布用户
- 对混合态配置、空字段、无入参 workflow 给显式提示
- 对当前用户组无权限的公共资源、RH 应用、RH 工作流，前台直接隐藏，不显示“拒绝使用”状态
- 服务商管理页的服务商轨道在桌面随页面 sticky，列表在视口内独立滚动；窄屏恢复静态单列布局。
- 统一权限页明确展示“已发布对象默认允许、这里只维护显式关闭”；管理员公共资源治理能力不出现在用户组或账号授权目录。

## 审计页当前结构

- 顶部：
  - 成功用量驾驶舱
  - 只统计 `succeeded` 任务
  - 数据来源是 `xh_tasks`，不是审计日志
- 驾驶舱模块：
  - KPI 条带：成功总数、图像、视频、RH AI 应用、RH 工作流、LLM
  - 能力占比环
  - 分组能量条
  - 账号排行榜
  - 每日趋势
  - 模型矩阵
  - RH 条目矩阵
- 底部：
  - 保留原来的审计日志表

## 审计页统计口径

- 图片 / 视频 / LLM：
  - 以模型显示名、模型 ID、Provider 展示
- RunningHub：
  - 以后台条目标题、catalogId、runTargetId 展示
- 账号与分组：
  - 删除账号仍保留成功次数桶，避免历史数据消失
  - 未分组账号归到 `ungrouped / 未分组`

## 组权限治理当前第一批落点

- 数据层：
  - 用户组策略已进入独立 `group permission policy` 模块和 migration
  - 支持 file / postgres 两种 auth storage 形态
- 后台接口：
  - 已新增分组权限策略读写接口
  - 已新增权限目录聚合接口
  - 已新增当前用户有效权限接口
- 前台用户体验：
  - 公共资源库按组策略直接隐藏不可用资源
  - RunningHub catalog 按组策略直接隐藏不可用条目
  - 旧画布残留条目仍由后端提交口兜底拦截
- 后台管理端当前结构：
  - `账号`
    - 顶部独立创建成员面板
    - 下方全宽账号表，负责组归属、备注、状态和密码治理
  - `用户组`
    - 改为大卡片式分组工作台
    - 支持更多分组，不再依赖小范围内嵌滚动条
    - 每个分组同时显示成员数、公共资源限制数、RH 限制数、节点限制数
  - `权限`
    - 左侧分组选择器
    - 右侧权限治理矩阵
    - 子区块分为 `公共资源 / RH AI 应用 / RH 工作流 / 节点能力`
    - 保存条固定在底部，明确显示未保存状态
    - 对目录暂时缺失的历史限制 ID 保留显示，不自动丢弃
  - `会话`
    - 独立展示活跃会话与撤销操作，不再和分组编辑混排
- 当前未完成：
  - 节点能力显式隐藏/锁定 UI 还在后续切片
  - 账号系统更深一层的分组权限治理、批量治理与视觉继续收口还在后续批次

## 2026-06-26 后台治理重构第一批落地

- 用户后台现在正式拆成 `账号 / 用户组 / 权限 / 会话` 四个稳定工作区：
  - `账号` 保留顶部独立创建成员面板和下方全宽账号表
  - `用户组` 改为左侧新建分组、右侧分组卡片墙
  - `权限` 改为左侧分组轨道、右侧摘要条带 + 分区编辑器 + 底部保存条
  - `会话` 独立显示活跃会话治理
- 用户组创建不再依赖中文名称 slug 作为唯一主键，改用系统生成的稳定唯一 ID。
- 创建分组失败时，错误只停留在分组表单内，不再升级为整页全局错误横幅。
- 权限页左侧分组卡片已降低高亮强度，右侧编辑器重新成为主视觉。
- 权限页页签和操作按钮现在遵循真实换行规则，不再靠横向滚动兜底。
- 公共资源后台已完成卡片化改造：
  - 左侧分类侧栏
  - 右侧自适应卡片网格
  - 上半区黑底 `contain` 预览框
  - 下半区参数与治理动作区
- 公共资源预览要求已同步到后台：
  - 图片完整显示
  - 视频在卡片和预览弹层中保持完整比例展示
  - 音频提供卡片内试听和弹层播放
  - 其他素材使用统一占位和完整预览入口

## 2026-06-27 后台治理重构第二批落地

- `组织与治理` 页顶部已加入治理概览条，聚合账号总数、普通成员、管理员、未分组账号和活跃会话。
- `用户组` 工作区已进入第二阶段 Starlight 结构：
  - 左侧继续保留创建轨道
  - 右侧改为带顶部概览条的分组工作台
  - 分组卡片细分为标题区、限制摘要区、编辑区和操作区
- `权限策略` 工作区已补齐顶部影响面板：
  - 当前筛选可配置条目
  - 当前分组已限制项
  - 目录缺失限制项
- `权限策略` 工作区现在继续遵循“说明 -> 影响 -> 批量操作 -> 对象列表 -> 保留项 -> 保存条”的治理节奏，不再直接把对象开关列表裸放到页面中心。
- RH / 节点能力权限对象改为稳定卡片信息层级，catalogId、runTargetId、nodeType id 进入单独元信息块，避免长文本把状态和操作区挤乱。
- 权限页左侧分组轨道继续保留，但主视觉已重新回到右侧编辑器和摘要区。
- `账号管理` 工作区已升级为“创建轨道 -> 治理概览 -> 巡检提示卡 -> 账号表”的治理节奏。
- `会话管理` 工作区已升级为“会话概览 -> 状态提示卡 -> 会话检查工具条 -> 会话表”的治理节奏。
- `成功用量驾驶舱` 已升级为“治理摘要条 -> KPI -> overview -> 图表 / 矩阵”的治理节奏。
- `组织与治理` 工作域现已先落一个总览首页，用于承接账号、分组、权限、会话和审计的快速下钻。
- 本轮继续把“文字不溢出、按钮不挤压、长 ID 不撑坏卡片”视为治理页功能需求处理，而不是后续样式补丁。
