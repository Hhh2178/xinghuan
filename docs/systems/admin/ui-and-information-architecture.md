# Admin 信息架构

## 当前信息架构重点

- 后台首页与系统页负责观测与治理
- RunningHub 工作台负责 RH 条目录入、分析、测试和启停
- 配置类页面需要明确区分“保存成功”和“实际生效”
- 审计页当前已升级为“成功用量驾驶舱 + 审计日志表”双层结构
- 用户与权限页下一阶段将以“账号 / 用户组 / 权限 / 会话”分区收口
  - `2026-06-26` 第一版已落地为顶部切换式工作台，不再把分组管理塞进窄侧栏

## RunningHub 工作台当前结构

- 左侧：搜索、分类、状态筛选、条目列表
- 右侧：基础信息、请求/响应示例、输入槽、参数 schema、输出定义、执行规则

## 页面命名原则

- 优先显示用户能理解的业务名称
- 参数有标注时优先显示标注
- 没有标注时回退技术字段名

## 视觉和交互要求

- 不把旧的 `Webapp ID` 等混淆文案暴露给画布用户
- 对混合态配置、空字段、无入参 workflow 给显式提示
- 对当前用户组无权限的公共资源、RH 应用、RH 工作流，前台直接隐藏，不显示“拒绝使用”状态

## 审计页当前结构

- 顶部：
  - 成功用量驾驶舱
  - 只统计 `succeeded` 任务
  - 数据来源是 `xh_tasks`，不是审计日志
- 驾驶舱模块：
  - KPI 条带：成功总数、图像、视频、RH AI 应用、RH 工作流、LLM
  - 能力占比环
  - 分组能量条
  - 账号排行榜
  - 每日趋势
  - 模型矩阵
  - RH 条目矩阵
- 底部：
  - 保留原来的审计日志表

## 审计页统计口径

- 图片 / 视频 / LLM：
  - 以模型显示名、模型 ID、Provider 展示
- RunningHub：
  - 以后台条目标题、catalogId、runTargetId 展示
- 账号与分组：
  - 删除账号仍保留成功次数桶，避免历史数据消失
  - 未分组账号归到 `ungrouped / 未分组`

## 组权限治理当前第一批落点

- 数据层：
  - 用户组策略已进入独立 `group permission policy` 模块和 migration
  - 支持 file / postgres 两种 auth storage 形态
- 后台接口：
  - 已新增分组权限策略读写接口
  - 已新增权限目录聚合接口
  - 已新增当前用户有效权限接口
- 前台用户体验：
  - 公共资源库按组策略直接隐藏不可用资源
  - RunningHub catalog 按组策略直接隐藏不可用条目
  - 旧画布残留条目仍由后端提交口兜底拦截
- 后台管理端当前结构：
  - `账号`
    - 顶部独立创建成员面板
    - 下方全宽账号表，负责组归属、备注、状态和密码治理
  - `用户组`
    - 改为大卡片式分组工作台
    - 支持更多分组，不再依赖小范围内嵌滚动条
    - 每个分组同时显示成员数、公共资源限制数、RH 限制数、节点限制数
  - `权限`
    - 左侧分组选择器
    - 右侧权限治理矩阵
    - 子区块分为 `公共资源 / RH AI 应用 / RH 工作流 / 节点能力`
    - 保存条固定在底部，明确显示未保存状态
    - 对目录暂时缺失的历史限制 ID 保留显示，不自动丢弃
  - `会话`
    - 独立展示活跃会话与撤销操作，不再和分组编辑混排
- 当前未完成：
  - 节点能力显式隐藏/锁定 UI 还在后续切片
  - 公共资源后台卡片化预览改造还在后续切片
