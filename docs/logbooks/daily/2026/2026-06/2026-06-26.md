### 灰度跨发布懒加载失配自恢复修复

目标:
- 修复灰度环境偶发的 `Failed to fetch dynamically imported module` 错误页
- 避免用户打开旧标签页跨过 gray 发布后，再点击懒加载节点时直接卡死在错误边界
- 保持现有静态资源缓存策略不变，只补一层前端一次性自恢复

根因:
- 用户截图显示前端仍停留在 `v0.5.4`
- 报错请求旧 chunk `LLMNode-Ca78BiPa.js`
- 当前 gray 已切到 `v0.5.5`，服务器实际存在的是新 chunk `LLMNode-DVsuHeI0.js`
- `/` 已返回 `cache-control: no-store`，并非旧 `index.html` 长缓存回退
- 真正触发链路是“旧页面壳跨过发布后，再按需懒加载一个已被新 release 替换掉的旧 chunk”

变更:
- 新增 `apps/web/src/utils/lazyImportRecovery.ts`
  - 识别 `Failed to fetch dynamically imported module` / `Importing a module script failed`
  - 通过 `sessionStorage` 记录一次性恢复标记
  - 首次命中 stale chunk 失配时自动 `reload()`，防止用户继续停留在错误页
  - 成功加载后清除恢复标记，避免后续正常会话受影响
- `apps/web/src/components/Canvas.tsx`
  - 画布内所有懒加载节点统一接入 `createLazyImportWithReloadRecovery`
- `apps/web/src/App.tsx`
  - 画布壳、资源库抽屉、生成库抽屉、主题管理器、RHToolsProvider 等壳层懒加载统一接入恢复逻辑
  - `preloadWorkspaceShell` 同步走相同恢复链路，避免壳层预加载与真正懒加载行为不一致
- 新增 `scripts/verify-web-lazy-import-recovery.ts`
- `package.json`
  - 新增 `verify:web-lazy-import-recovery`

验证:
- `npm run verify:web-lazy-import-recovery`
- `npm run type-check -w @xinghuan/web`
- `npm run build -w @xinghuan/web`
- `npm run verify:app-shell-loading-announcement-contract`

影响:
- gray 发布期间，如果用户仍开着旧壳页面，再触发新的懒加载模块时，会自动硬刷新一次进入新版本
- 普通渲染错误不会误触发这条恢复逻辑
- 同一会话里若刷新后仍失败，不会进入无限刷新循环

风险:
- 这轮修复针对的是前端 stale chunk 失配，不覆盖真正的网络断连或发布目录损坏
- 线上仍需继续观察是否还有极少量浏览器对动态导入失败抛出不同文案

下一步:
- 提交这次 bugfix
- 如需继续 gray 发布，再补 release/ops 记录并部署验证
