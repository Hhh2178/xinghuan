# 2026-07-26

## Video Prompt Provider-Side Limit Repair

- Root cause: the AICOPY SD contract added `advancedConfig.maxPromptBytes` handling, and the resolver also supplied a default 4096 limit. AIFork uses `protocol=aicopy`, so an AIFork SD prompt was rejected in API validation before it entered the provider task queue, even when the provider catalog had no such limit.
- Fix: video prompt byte preflight is disabled for every protocol. Historical `maxPromptBytes` values are ignored for admission; the request reaches the provider, whose response becomes the user-visible error. The existing platform prompt safety ceiling remains unchanged.
- Added regression coverage proving AICOPY/AIFork and other protocols ignore residual `4096` configuration. No provider credentials or production data were touched.
