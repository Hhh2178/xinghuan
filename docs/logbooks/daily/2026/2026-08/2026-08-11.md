## Provider 多模态图片回抓 404 审查

- 复核 MIMO 与柏拉图图片分析失败后，确认共同症状是上游收到的 `files` 域名图片地址返回 HTTP 404；这不是模型本身不支持图片。
- 根因：应用新增了 `/api/provider-media/{token}`，但 Files Nginx 仅代理 `/api/provider-files/{scope}/`；`files` 默认 location 返回 Nginx 404。同时新路径没有环境 scope，无法在一个共享 Files 域名上安全分流到 Gray 或 Production。
- 修复：签名媒体地址调整为 `/api/provider-media/{scope}/{token}`；API 同时校验 URL scope、运行环境和 token claim scope；Files Nginx 模板为 Gray/Production 分别增加只读代理路由。
- 回归：媒体引用、路由和 Nginx 边缘契约共 8 项通过；API 构建及完整测试通过（998 passed，4 skipped）。
- 本记录只覆盖代码与模板验证，尚未将本次修复部署到服务器；部署后必须以真实签名图片完成 Files 域名回抓验收。
