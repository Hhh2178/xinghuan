# Gray Release Standard Checklist

适用环境：`canvas-next.hhh2121.xyz` / `127.0.0.1:18200`

## Agent 必做

### 发布前

- 确认本轮版本号已经推进，且内部依赖版本已对齐。
- 确认工作树只包含本轮预期改动。
- 执行本地构建。
- 执行本轮要求的契约 / 类型 / 发布包校验。
- 生成 release 包并确认包路径存在。

### 发布中

- 上传 release 包到灰度服务器。
- 在远端创建新 release 目录。
- 执行 `npm ci`。
- 切换 `current` 指向新 release。
- 重启 `xinghuan-canvas-next.service`。
- 重启 `xinghuan-canvas-next-worker.service`。

### 发布后

- 验证 `current` 指针。
- 验证两个 systemd 服务都为 `active`。
- 验证内网 `http://127.0.0.1:18200/api/status`。
- 验证公网 `https://canvas-next.hhh2121.xyz/api/status`。
- 如本轮涉及数据库目标，验证当前数据库名符合预期。
- 同步发布记录、当前 release 索引和主入口状态。
- 输出 `Agent 已验证 / 待用户验收` 两段式结论。

## 用户必做

### 灰度视觉验收

- 打开首页，确认首屏视觉和布局符合预期。
- 打开后台，确认关键页面观感、对齐、层级、文案符合预期。
- 如本轮涉及节点或编辑器，确认灰度页面中的实际视觉表现符合预期。

### 真实业务链路验收

- 以真实业务方式走关键流程。
- 确认交互反馈、结果内容、业务输出质量符合预期。
- 给出是否放行、继续观察或退回修正的结论。

## 边界说明

- Agent 默认不把视觉层和主观体验层验收算作自己已完成的验证。
- 用户未完成视觉与业务体验验收前，发布结论应表述为“代码 / 架构 / 运行态已验证，待用户验收”。
