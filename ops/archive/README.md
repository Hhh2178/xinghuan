# ops/archive - 历史运维记录归档

本目录用于存放已经脱离“当前运行入口”职责，但仍需要保留为审计证据的历史运维记录。

归档原则：

- 当前仍用于部署、验收、值守的文档留在 `ops/` 根目录
- 已完成阶段、已被新记录覆盖的历史材料移入 `ops/archive/`
- 不删除已归档记录，除非后续另有明确清理决策

当前阶段归档批次：

- `2026-06-initial-rollout/`
  - 2.0 初始灰度、认证、后台、安全、数据库切换、旧画布清理等第一轮落地材料
- `2026-06-assistant-and-ui-rollout/`
  - 2026-06-08 到 2026-06-10 的本机清理、Hermes 联调、助手 UI、生成数量早期闭环记录
- `2026-06-provider-and-infra-rollout/`
  - 2026-06-12 的 Provider 任务化、并发治理、ModelScope 协议、Cloudflare 与 files 域名切换阶段记录
- `2026-06-phase3-rollout/`
  - Phase 3 初期灰度、生产切换、节点验收、入口 UI 和首轮产品闭环发布材料

维护要求：

- 只要 `ops/README.md` 的当前入口移出了某一批历史记录，就必须同步补一个归档批次说明或更新现有批次说明。
- 归档批次的 `README.md` 至少要说明：
  - 这一批收了什么
  - 为什么它们不再属于当前运行态入口
  - 推荐从哪几份记录开始回看
