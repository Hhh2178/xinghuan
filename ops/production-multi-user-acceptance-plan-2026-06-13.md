# 正式环境多用户加固验收测试方案（2026-06-13）

## 用途

本清单用于后续多用户正式化加固的灰度验收、正式放行和回滚判断。

适用范围:

- 画布仓储与保存协议重构
- 资源库与生成库仓储重构
- Auth / Session / Admin 仓储重构
- 任务状态机、取消和审计加固

## 放行原则

- 先灰度，后正式。
- 先数据保全，后功能扩展。
- 任一 P0 用例失败，禁止上线正式。
- 任一“用户数据被覆盖 / 被清空 / 被转移 owner”用例失败，禁止上线正式。

## 上线前准备

- 确认灰度和正式数据库目标防呆仍生效。
- 生成当前 `xh_canvases`、`xh_assets`、`xh_tasks`、`xh_sessions` 统计快照。
- 记录当前 release 指针、数据库名、环境变量文件路径。
- 准备至少 3 个测试账号：
  - `admin`
  - `member-a`
  - `member-b`
- 准备至少 2 个浏览器会话：
  - 同账号双标签页
  - 跨账号双会话

## A. 数据归属验收

### A1 画布创建与归属

- `member-a` 新建 2 个画布。
- `member-b` 新建 2 个画布。
- 验证双方只可看到自己的画布列表。
- 验证数据库中 4 条记录的 `owner_id` 正确。

通过标准:

- 无串号。
- 无丢失。

### A2 伪造画布 ID 更新

- 用 `member-b` 身份尝试保存 `member-a` 的画布 `id`。
- 尝试 `PUT /api/canvas/:id`。
- 尝试 `POST /api/canvas/:id/auto-save`。

通过标准:

- 服务端拒绝写入。
- `owner_id` 不发生变化。
- 原画布内容不变。
- 返回明确错误，不允许静默成功。

### A3 旧列表覆盖回归

- `member-a` 在浏览器会话 1 打开旧画布列表。
- 在会话 2 新建一个新画布。
- 回到会话 1 执行重命名、排序或保存。

通过标准:

- 会话 1 不会把会话 2 新建的画布从服务器删除。
- 若存在版本冲突，返回冲突提示，不允许静默覆盖。

## B. 并发与版本化验收

### B1 同画布双标签并发保存

- 同一账号打开同一画布两个标签页。
- 标签页 A 先保存节点改动。
- 标签页 B 基于旧版本再保存不同内容。

通过标准:

- 不会静默覆盖 A 的最新保存。
- B 至少收到冲突提示或需要刷新后再保存。

### B2 后台配置并发写入

- 两个管理员会话同时修改同一 Provider。
- 两个管理员会话同时修改同一 Model。
- 两个管理员会话同时修改 AI 助手设置。

通过标准:

- 不会因为后写入覆盖掉先写入的无关字段。
- 不会触发整库回写造成其他 Provider / Model / Task 丢失。

## C. 会话与权限验收

### C1 登录限流

- 对同一账号连续输入错误密码。
- 对同一 IP 连续尝试多个错误账号。

通过标准:

- 达到阈值后接口被限流或短暂锁定。
- 合法登录在阈值恢复后仍可正常使用。

### C2 CSRF 防护

- 构造不带合法 CSRF 的写请求。
- 覆盖用户、Provider、画布、任务取消等写接口。

通过标准:

- 请求被拒绝。
- 不产生副作用。

### C3 会话可治理

- 后台查看会话列表。
- 强制下线某一个会话。

通过标准:

- 被下线会话立即失效。
- 其他会话不受影响。

## D. 任务与取消验收

### D1 本地取消与上游取消区分

- 分别测试：
  - 支持 upstream cancel 的 Provider
  - 不支持 upstream cancel 的 Provider

通过标准:

- 返回状态明确区分：
  - `local_cancelled_only`
  - `upstream_cancel_confirmed`
  - `upstream_cancel_not_supported`

### D2 长任务补偿

- 提交一个长视频任务。
- 人工中断 worker 或暂停轮询。
- 恢复服务后检查任务是否被重新复核。

通过标准:

- 任务不会永久卡死在 `running`。
- 后台能看到补偿日志。

## E. 审计与可观测性验收

### E1 审计字段

- 执行用户创建、Provider 修改、任务取消、AI 助手配置变更。

通过标准:

- 审计日志包含：
  - `actor`
  - `action`
  - `target`
  - `ip`
  - `user_agent`
  - `request_id`

### E2 请求链路

- 对单个失败任务，从前端报错追到 API 日志、Worker 日志、数据库记录。

通过标准:

- 可通过 `taskId` / `requestId` 串起整条链路。

## F. 性能与分页验收

### F1 后台任务分页

- 构造 1000+ 任务数据。
- 打开后台任务页。

通过标准:

- 接口为分页读取，不是全量返回。
- 首屏响应时间可接受。

### F2 素材库分页

- 构造 1000+ 资源数据。
- 打开资源库与生成库。

通过标准:

- 接口可分页或分批读取。
- 不因全量 JSON 返回造成界面卡死。

## G. 灰度放行条件

- A 全部通过。
- B 全部通过。
- C 至少完成基础限流、CSRF、会话下线。
- D 至少完成取消语义区分和一轮补偿测试。
- E 至少完成审计字段和请求链路串联。
- 构建、类型检查、关键契约脚本全部通过。

## H. 正式放行条件

- 灰度连续运行一个观察周期无数据异常。
- 灰度多账号并发保存无画布丢失。
- 正式上线前完成数据库快照和 release 回滚点记录。
- 正式验收重复执行 A1、A2、B1、D1、E1 的精简版冒烟。

## I. 立即回滚条件

- 任何用户画布数量异常减少。
- 任何用户素材库被整体替换或清空。
- 任意跨用户 owner 变化。
- 登录态大面积丢失。
- 后台 Provider / Model / Task 数据异常回退。

## J. 建议附带脚本

- 画布 owner 防串改验证脚本
- 双标签并发保存冲突验证脚本
- 后台 Provider 并发修改验证脚本
- 任务取消语义验证脚本
- 审计字段完整性验证脚本
